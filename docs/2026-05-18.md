### JSP & Servlet 

#### 웹 동작 원리

브라우저가 URL로 요청을 보내면, 웹 서버(Apache)가 요청을 받아 WAS(Tomcat)로 전달한다.
Tomcat은 JSP/Servlet 엔진을 통해 자바 코드를 처리하고, 최종적으로 HTML을 추출해 브라우저에 응답한다.

```
브라우저 → 웹 서버(Apache) → WAS(Tomcat) → JSP/Servlet 처리 → HTML 응답 → 브라우저
```

> 브라우저가 받는 건 항상 **HTML**이다. JSP나 Servlet 코드 자체가 전달되는 게 아니다.

---

#### JSP & Servlet 

두 기술 모두 동적 웹페이지를 만들기 위한 도구지만, 중심이 다르다.

|  | Servlet | JSP |
|--|---------|-----|
| 중심 | Java | HTML |
| 수정 후 확인 | 재컴파일 필요 | 저장하면 즉시 반영 |
| 코드 길이 | 길다 | 짧다 |
| CSS / JS 작성 | 불편하다 | 바로 사용 가능 |
| 소스 노출 | 노출되지 않음 | 노출 가능 |
| 확장성 | 좋다 | 상대적으로 낮다 |

둘의 단점을 서로 보완하는 구조로 사용한다.

```
보안 / 비즈니스 로직  →  Servlet
화면 출력            →  JSP
```

이게 MVC 패턴의 기반이 된다.

#### Servlet 생명주기

Servlet은 한 번 생성된 후 요청이 들어올 때마다 재사용된다. 생성과 소멸은 단 한 번씩만 일어난다.

```
최초 요청
  └─ Servlet 객체 생성
       └─ init()       ← 딱 1번
            └─ service()  ← 요청마다 반복
                 └─ destroy()  ← 서버 종료 시 딱 1번
```

#### `init()`
- 서블릿이 생성될 때 **딱 1번** 실행
- DB 연결 준비, 설정 파일 로딩 등 초기화 작업 처리

#### `service()` — `doGet()` / `doPost()`
- 클라이언트 요청이 올 때마다 실행
- 요청 방식에 따라 분기된다

| 방식 | 특징 | 주요 사용처 |
|------|------|-------------|
| GET | URL에 데이터 노출 (`?key=value`) | 목록 조회, 상세보기, 검색 |
| POST | 데이터를 내부에 숨겨서 전송 | 로그인, 회원가입, 파일 업로드 |

요청 처리 순서는 보통 아래 흐름을 따른다.
1. 요청 데이터 받기
2. DB 처리
3. 비즈니스 로직 처리
4. 응답 (JSP로 이동)

#### `destroy()`
- 서버 종료 시 **딱 1번** 실행
- DB 연결 해제, 메모리 정리, 로그 저장

#### JSP 동작 방식

JSP는 내부적으로 Servlet으로 변환되어 실행된다. 생명주기 메서드 이름만 다를 뿐 동작은 동일하다.

| Servlet | JSP | 실행 시점 |
|---------|-----|-----------|
| `init()` | `jspInit()` | 최초 1번 |
| `service()` | `_jspService()` | 요청마다 |
| `destroy()` | `jspDestroy()` | 종료 시 1번 |

JSP 문법은 HTML 안에 자바 코드를 삽입하는 방식이다.

```jsp
<%  자바 코드 실행 (출력 없음)  %>
<%= 값 출력 %>
<%@ 지시자 (import, page 설정 등) %>
```

#### Tomcat 버전별 패키지 차이

```java
Tomcat 10 이상  →  jakarta.servlet
Tomcat 9 이하   →  javax.servlet
```

버전에 따라 import 경로가 다르므로 프로젝트 설정 시 Tomcat 버전을 반드시 확인해야 한다. (실무에서 유지보수 시 이전 버전을 마주 칠 수 있음)
