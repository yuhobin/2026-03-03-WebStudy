### JSP (Java Server Pages) 복습

#### JSP란?

> 서버에서 실행되는 Java 파일로, 내부적으로 **Servlet으로 변환**되어 실행된다.

```
JSP 파일 → Servlet 변환 → 컴파일 → 실행
                              ↓
                    out.write("<html>") ...
                              ↓
                    메모리에 저장 (출력 서버)
                              ↓
                    해당 브라우저에서 읽어서 출력
```

---

#### JSP 실행 단계

```
1. 클라이언트 요청 (URL 입력)
   예) http://localhost/JSPBasicProject/jsp/a.jsp

2. 웹서버가 URL 주소를 받는다

3. a.jsp 파일 탐색
   => 존재(O) → 톰캣으로 전송
   => 존재(X) → 브라우저로 404 전송

4. 톰캣이 JSP → Servlet 변환 후 컴파일 및 실행
   => a.jsp → a_jsp.class (HttpServlet 상속)

5. 실행 결과를 브라우저에 출력
```

#### 톰캣 변환 결과 예시

```java
class a_jsp extends HttpServlet {
    public void _jspInit()    { }  // 초기화 (1회만 실행)
    public void _jspDestroy() { }  // 메모리 해제
    public void _jspService() {    // 요청 처리 & 응답 생성
        // 메모리에 저장된 HTML 출력
    }
}
```

#### 전체 흐름 요약

```
브라우저 요청 (URL)
       ↓
JSP 파일 확인
       ↓
JSP → Servlet 변환
       ↓
Servlet 컴파일
       ↓
서블릿 객체 생성
       ↓
_jspInit() 호출
       ↓
_jspService() 실행
       ↓
HTML 응답
       ↓
_jspDestroy()
```

---

#### JSP 생명주기 메서드

| 메서드 | 호출 시점 | 설명 |
|---|---|---|
| `_jspInit()` | 최초 1회 | 초기화 (web.xml 설정 반영) |
| `_jspService()` | 매 요청마다 | 요청 처리 / 응답 생성 |
| `_jspDestroy()` | 종료 시 | 메모리 해제 |

---

#### Servlet vs JSP 비교

| 구분 | Servlet | JSP |
|---|---|---|
| **중심** | Java 기반 (class) | HTML 기반 |
| **화면 UI** | `out.write("<html>")` → 불편 | `<html>` 직접 작성 → 편리 |
| **유지보수** | 어렵다 | 상대적으로 쉽다 |
| **역할** | Controller (HTML/Java 연결) | View (화면 UI) |

---

#### 실무 활용

```
과거  │ Servlet + JSP → MVC 패턴 (Spring Framework)
      │ 공기업 / 일부 SI에서 아직 사용 중
현재  │ Spring Boot + Thymeleaf  → 배포 파일이 작다 (.jar)
      │ Spring Boot + Vue.js / React.js
```

#### JSP 학습 순서

```
1. 동작 과정 흐름 파악
2. 스크립트          : <% %>, <%= %>, <%! %>
3. 지시자
   => page           : 파일 정보 (import, buffer, session, contentType ...)
   => taglib         : 태그로 Java 제어문 / 라이브러리 사용
   => include        : 특정 위치에 다른 JSP 삽입 (조립식)
4. 내장 객체
   => request / response / session
   => out / pageContext / application   ==> 여기까지 6개는 반드시 숙지할것
   => config / exception / page
5. JSP 액션 태그     : <jsp:forward>, <jsp:include> ...
6. Cookie 사용법
7. 데이터베이스 연동 : ConnectionPool
──────────────────────────────────────
8. JSTL / EL
9. MVC 구조
```

#### 지시자 - `page`

> JSP 파일 상단에 작성하는 가장 기본적인 지시자

```
형식) <%@ page 속성="값" %>
```

#### 주요 속성

**1) `language` - 사용 언어 지정**
```jsp
<%@ page language="java" %>
```

**2) `contentType` - 응답 타입 지정**
```jsp
<%@ page contentType="text/html; charset=UTF-8" %>
```

| 값 | 설명 |
|---|---|
| `text/html` | HTML |
| `text/xml` | XML |
| `text/plain` | JSON 등 일반 텍스트 |
| `charset=UTF-8` | 한글 포함 시 지정 |

**3) `import` - Java 라이브러리 로드**
```jsp
<%@ page import="java.util.*, java.io.*" %>
<%@ page import="java.util.*" %>
<%@ page import="java.io.*" %>
```
>  `import`는 유일하게 **여러 번 선언 가능**한 속성

**4) `pageEncoding` - 한글 깨짐 방지**
```jsp
<%@ page pageEncoding="UTF-8" %>
```

###  JSP 에러 페이지 처리

> HTTP 에러(404, 500 등) 발생 시 사용자에게 보여줄 **커스텀 에러 페이지**를 미리 만들어두고, 에러 발생 시 해당 페이지로 자동 이동하도록 설정

#### 동작 흐름

```
사용자 요청
    ↓
에러 발생 (예: 404 - 페이지 없음)
    ↓
web.xml 에러 설정 확인
    ↓
지정된 에러 JSP 페이지로 이동
    ↓
사용자에게 커스텀 에러 화면 출력
```

#### 설정 방법

**1) `web.xml` - 에러 코드별 이동 페이지 등록**

```xml
<!-- 404 에러 -->
<error-page>
    <error-code>404</error-code>
    <location>/error/404.jsp</location>
</error-page>

<!-- 500 에러 -->
<error-page>
    <error-code>500</error-code>
    <location>/error/500.jsp</location>
</error-page>
```

**2) 에러 페이지 JSP - `isErrorPage` 속성 지정**

```jsp
<%@ page isErrorPage="true" %>
```

> `isErrorPage="true"` 를 선언해야 해당 파일이 에러 페이지임을 인식하고,  
> `exception` 내장 객체를 사용할 수 있다.

#### 주요 에러 코드

| 코드 | 설명 |
|---|---|
| `400` | Bad Request - 잘못된 요청 |
| `403` | Forbidden - 접근 권한 없음 |
| `404` | Not Found - 페이지 없음 |
| `500` | Internal Server Error - 서버 내부 오류 |

### CSS Position 속성

> 요소의 배치 방식을 결정하는 `position` 속성 정리

| 값 | 설명 |
|---|---|
| `static` | HTML 문서의 기본 흐름에 따라 배치. `top` / `left` / `bottom` / `right` 적용 안 됨 |
| `absolute` | **가장 가까운 위치 지정 부모 태그**를 기준으로 배치 |
| `relative` | **원래 자리**를 기준으로 지정한 만큼 이동 |
| `fixed` | **고정 좌표** - 스크롤해도 위치 변하지 않음 |
| `sticky` | 평소엔 흐름 따라가다, **스크롤 시 특정 위치에서 고정** |

#### 특성 비교

```
static   → top/left/right/bottom 무시됨, 기본값
relative → 원래 공간은 유지하면서 시각적으로만 이동
absolute → 부모 중 position이 지정된 요소 기준 (없으면 <body> 기준)
fixed    → 브라우저 뷰포트 기준, 스크롤 영향 없음
sticky   → 스크롤 임계점 도달 시 fixed처럼 동작
```

### 💡 Note
JSP의 흐름 파악을 복습하고 추가로 에러페이지를 만들어 연결해보는 연습을 했다
확실히 스크립트 사용하는 과정에서 오탈자로 에러가 자주 발생한다. 이부분은 구조를 확실하게 눈에 익혀서 구조를 파악할 수 있게 해야할 것 같다.
일단 지금은 자바코드 부분을 덩어리호 생각해서 그걸  감싼다는 생각으로 구분하고 있다. 반면 HTML코드는 감싸지지 않는지 확인하며 작성하는데
확실히 하나하나 확인하느라 시간이 오래 걸린다.
