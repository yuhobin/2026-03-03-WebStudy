#### 1. JSP 내장 객체 개요

| 내장 객체 | 실제 타입 | 역할 |
|---|---|---|
| `request` | `HttpServletRequest` | 클라이언트 요청 정보 |
| `response` | `HttpServletResponse` | 서버 응답 처리 |
| `session` | `HttpSession` | 서버 측 사용자 데이터 유지 |
| `out` | `JspWriter` | 출력 버퍼 제어 (`<%= %>`, `${}`) |
| `application` | `ServletContext` | 서버(애플리케이션) 전역 정보 |
| `pageContext` | `PageContext` | 내장 객체 관리, include/forward |
| `exception` | `Exception` | 예외 처리 (에러 페이지 전용) |
| `page` | `Object` | 현재 JSP 페이지 자신 (`this`) |
| `config` | `ServletConfig` | web.xml 환경 설정 |

#### 2. `request` 객체 — `HttpServletRequest`

클라이언트가 브라우저 주소창이나 폼을 통해 서버로 보낸 **모든 요청 정보**를 담고 있다.

```
http://localhost/MyProject/jsp/request.jsp
|_______________|___________________________|
   서버 정보               요청 정보 (URL)
```

---

#### 2.1 서버 정보

```java
request.getServerName()   // 서버 이름 (예: localhost)
request.getProtocol()     // 프로토콜 (예: HTTP/1.1)
request.getMethod()       // 전송 방식 (GET / POST / DELETE / PUT)
```

---

#### 2.2 클라이언트 & URL 정보

```java
request.getRemoteAddr()    // *** 클라이언트 IP 주소
request.getServerPort()    // 포트 번호 (기본 80, 개발 환경 8080 등)
request.getRequestURL()    // 전체 URL
request.getRequestURI()    // *** 컨텍스트 경로 포함 URI
request.getContextPath()   // *** 컨텍스트 경로 (예: /MyProject)
```

---

#### 2.3 사용자 요청 파라미터

> **웹에서 전송되는 모든 데이터는 `String` 타입**이다.  
> 숫자 등 다른 타입이 필요할 경우 반드시 **형변환** 처리한다.

#### 단일 값 읽기
`text`, `password`, `file`, `date`, `radio` 등 단일 입력 요소

```java
String value = request.getParameter("name속성값");
```

**URL 쿼리스트링으로 전달하는 경우:**
```
main.jsp?no=10
         └─ key=value 형태, key 중복 불가 (Map 구조)
```

```java
String no = request.getParameter("no"); // "10"
int num = Integer.parseInt(no);         // 형변환 필요
```

#### 다중 값 읽기
`checkbox`, `<select multiple>` 등 복수 선택 요소

```java
String[] values = request.getParameterValues("name속성값");
```

---

#### 2.4 한글 인코딩

브라우저는 데이터를 **바이트(byte[])로 인코딩**해서 전송한다.  
POST 방식에서 한글이 깨질 경우 **요청 처리 전** 가장 먼저 선언해야 한다.

```java
request.setCharacterEncoding("UTF-8");
```

> **GET 방식**은 서버(Tomcat) 설정 또는 운영체제(Windows 11+)에서 자동 처리되는 경우가 많다.

---

#### 2.5 속성 공유 (`setAttribute` / `getAttribute`)

MVC 패턴에서 **Controller → JSP(View)** 로 데이터를 전달할 때 주로 사용한다.  
`forward`와 함께 써야 `request` 객체가 유지된다.

```java
// Controller (Servlet)에서 데이터 저장
request.setAttribute("user", userObject);

// JSP에서 데이터 읽기 (Object 반환 → 형변환 필요)
User user = (User) request.getAttribute("user");
```

| 구분 | 설명 |
|---|---|
| `setAttribute(String key, Object value)` | 데이터를 request 범위에 저장 |
| `getAttribute(String key)` | 저장된 데이터를 `Object`로 반환 |

#### 3. `response` 객체 — `HttpServletResponse`

서버가 클라이언트(브라우저)에게 **응답을 전송**할 때 사용한다.

> ⚠️ 한 번의 요청에 **응답은 하나**만 가능하다. (파일 하나만 전송)

---

#### 3.1 응답 콘텐츠 설정

```java
response.setContentType("text/html;charset=UTF-8"); // HTML 응답
response.setContentType("application/json;charset=UTF-8"); // JSON 응답
```

#### 쿠키 전송

```java
Cookie cookie = new Cookie("쿠키명", "값");
response.addCookie(cookie);
```

#### 헤더 사전 설정 (파일 다운로드, JSON 전송 등)

```java
response.setHeader("Content-Disposition", "attachment;filename=file.xlsx");
```

---

#### 3.2 화면 이동 — `sendRedirect`

```java
response.sendRedirect("이동할 파일명 또는 URL");
```

- 전송 방식: **GET**
- 브라우저가 **새로운 요청**을 다시 보내는 방식 (URL이 변경됨)

**대표 사용 패턴 — POST 후 목록으로 이동:**
```
[사용자 입력] → insert.jsp → insert_ok.jsp → sendRedirect("list.jsp")
                                └── DB 처리
```

| 장점 | 단점 |
|---|---|
| URL이 바뀌므로 새로고침 시 중복 제출 방지 | `request` 객체가 초기화됨 (데이터 유지 불가) |

---

#### 3.3 `forward`와의 비교

| 구분 | `sendRedirect` | `forward` |
|---|---|---|
| 처리 주체 | 브라우저가 새 요청 | 서버 내부에서 이동 |
| URL 변경 | ✅ 변경됨 | ❌ 변경 안 됨 |
| `request` 유지 | ❌ 초기화 | ✅ 유지됨 |
| 주 사용 목적 | INSERT/DELETE 후 목록 이동 | MVC에서 Controller → View 이동 |
| JSP 태그 | — | `<jsp:forward>` |

```java
// forward 방식 (pageContext 또는 RequestDispatcher 사용)
pageContext.forward("view.jsp");

// 또는
RequestDispatcher rd = request.getRequestDispatcher("view.jsp");
rd.forward(request, response);
```

#### 4. HTTP 전송 방식 (Method)

RESTful 설계 기준으로 각 메서드는 다음 역할을 담당한다.

| Method | 역할 | SQL 대응 |
|---|---|---|
| `GET` | 데이터 조회 / 화면 출력 | SELECT |
| `POST` | 데이터 전송 및 저장 | INSERT |
| `PUT` | 데이터 전체 수정 | UPDATE |
| `DELETE` | 데이터 삭제 | DELETE |

> 웹 브라우저 폼(`<form>`)은 기본적으로 **GET / POST**만 지원한다.  
> DELETE · PUT은 JavaScript(fetch, axios) 또는 REST API 클라이언트에서 사용한다.

---

#### 5. 흐름 요약

```
[브라우저]
    │  HTTP Request (URL, 파라미터, 헤더)
    ▼
[서버 — request 객체]
    ├─ getParameter()        ← 폼 데이터 / 쿼리스트링
    ├─ getRequestURI()       ← 요청 경로
    ├─ getRemoteAddr()       ← 클라이언트 IP
    └─ setAttribute()        ← Controller → View 데이터 전달
    │
    │ 처리 결과
    ▼
[서버 — response 객체]
    ├─ setContentType()      ← 응답 타입 설정
    ├─ addCookie()           ← 쿠키 전송
    └─ sendRedirect()        ← 다른 페이지로 이동 (GET)
    │
    │  HTTP Response (HTML / JSON / 파일)
    ▼
[브라우저]
```

---

> 📌 **핵심 정리**
> - `request` : 클라이언트가 보낸 모든 정보를 읽는다.
> - `response` : 서버가 클라이언트에게 결과를 보낸다.
> - 데이터를 다음 JSP로 넘길 때 → **`setAttribute` + `forward`** (request 유지)
> - 처리 후 다른 페이지로 이동할 때 → **`sendRedirect`** (중복 제출 방지)
