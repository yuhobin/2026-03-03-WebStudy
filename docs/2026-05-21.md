#### 왜 필요한가?

> HTTP는 기본적으로 **Stateless** 구조 → 요청이 끝나면 서버가 클라이언트를 잊어버린다

```
로그인 → 다음 페이지 이동 → 서버 : "이 사람 누구지?"
장바구니 → 다음 페이지 이동 → 담았던 상품이 사라진다
```

→ 사용자를 **기억**하기 위해 Cookie / Session이 필요

---

### Cookie

> 데이터를 **클라이언트(브라우저)** 에 저장

#### 주요 메서드

```java
// 1. 쿠키 생성 (key 중복 시 덮어씀)
Cookie cookie = new Cookie("key", "value");
cookie.setMaxAge(60 * 60 * 24);  // 유지 시간 설정 (하루)
cookie.setPath("/");              // 저장 경로
response.addCookie(cookie);       // 브라우저로 전송

// 2. 쿠키 읽기
Cookie[] cookies = request.getCookies();
for (Cookie c : cookies) {
    c.getName();   // key 읽기
    c.getValue();  // value 읽기
}

// 3. 쿠키 삭제
cookie.setMaxAge(0);

// 4. 쿠키 수정
Cookie cookie=new Cookie("a1", "aaa");
Cookie cookie=new Cookie("a1", "bbb");  // 값이 aaa에서 bbb로 수정
```

#### 주요 사용처
- 자동 로그인
- 최근 방문 / 최근 본 상품
- 팝업 "오늘 하루 안 보기"

---

### Session

> 데이터를 **서버**에 저장 / JSP 내장 객체로 바로 사용 가능

#### 주요 메서드

```java
// 1. 저장 (value는 Object 타입 → ArrayList, VO 등 모두 가능)
session.setAttribute("key", value);

// 2. 읽기
session.getAttribute("key");

// 3. 일부 삭제
session.removeAttribute("key");

// 4. 전체 삭제 (로그아웃)
session.invalidate();

// 5. 유지 시간 설정 (기본값 1800초 = 30분)
session.setMaxInactiveInterval(1800);
```

#### 특징
- 사용자마다 **개별 공간** 할당 → `session.getId()`로 구분
- 브라우저 종료 / 로그아웃 시 자동 삭제
- Cookie와 달리 **Object 타입** 저장 가능

#### 주요 사용처
- 로그인 상태 유지
- 장바구니, 예약
- 관리자 인증

---

#### Cookie vs Session 비교

> * 면접 단골 질문

| 구분 | Cookie | Session |
|---|---|---|
| **저장 위치** | 클라이언트(브라우저) | 서버 |
| **보안** | 낮음 | 높음 |
| **용량** | 작다 (4KB) / 문자열만 | 크다 / Object 가능 |
| **유지** | 설정한 만료일까지 | 브라우저 종료 / 로그아웃 시 삭제 |
| **속도** | 빠름 | 상대적으로 느림 (서버 경유) |
| **용도** | 자동 로그인, 최근 방문 | 로그인 유지, 장바구니, 예약 |

---

#### 실무 사용 기준

```
로그인 상태 유지    →  Session (무조건)
자동 로그인         →  Cookie  (Spring : remember-me)
장바구니            →  Session 또는 DB
소셜 로그인 (JWT)   →  Cookie 기반

가벼운 데이터       →  Cookie
보안이 필요한 데이터 →  Session
```

### 💡 Note
Cookie와 Session은 JSP에서만 사용하는 일부 내장 객체들과 달리 나중에 Spring에서도 재등장하기 때문에 반드시 개념파악을 하고 있어야한다.(중요 개념)

Cookie와 Session비교 외에 사이트 조립하는 방식을 익혔는데

사이트 템플릿을 활용하여 main, home, header, footer 부분으로 나누고 <jsp:include>을 활용하여 조립하였다.

이 방식이 유용한 점은 한 페이지를 만들더라도 따로 나누어 만들 수 있기에 협업에 유리하다.
