### 왜 필요한가?

JSP는 HTML + Java + DB가 한 파일에 뒤섞여 유지보수가 어렵고 협업이 불편하다.
EL과 JSTL은 JSP 안의 자바 코드를 최대한 줄이고 태그 형식으로 대체해 이 문제를 해결한다.

```
기존 방식  →  <% %>, <%= %>  : Java 코드가 HTML 사이에 섞임
EL/JSTL   →  ${}, <c:~>     : 태그 형식으로 대체 → 유지보수 편리 / 협업 용이
```

> Spring에서도 EL / JSTL을 그대로 사용한다. 실무에서 반드시 쓰이는 문법이다.

### EL (Expression Language)

> `<%= %>` 를 대체하는 화면 출력 표현식

#### 기본 문법

```jsp
<!-- 기존 방식 -->
<%= request.getAttribute("name") %>

<!-- EL 방식 -->
${name}
```

#### 내장 객체

| EL 표현 | 대응하는 Java 코드 |
|---|---|
| `${requestScope.key}` | `request.getAttribute("key")` |
| `${sessionScope.key}` | `session.getAttribute("key")` |
| `${applicationScope.key}` | `application.getAttribute("key")` |
| `${param.key}` | `request.getParameter("key")` |
| `${paramValues.key}` | `request.getParameterValues("key")` |

#### 연산자

```jsp
${5 + 2}        산술 : + - * / %
${5 / 2}        → 2.5  (정수 / 정수 = 실수)
${"5" += "4"}   → "54" (문자열 결합은 +=)
${"5" + "4"}    → 9    (+ 는 숫자 덧셈만, 문자열도 자동으로 숫자 변환)
${5 + null}     → 5    (null은 0으로 인식)

${a == b}       비교 : == != < > <= >=
${a and b}      논리 : and or not
${a ? b : c}    삼항 연산자
${empty a}      empty : null 또는 빈 값 여부 확인
```

### JSTL (Java Standard Tag Library)

> `<% %>` 를 대체하는 태그 라이브러리 / XML 문법 기반

#### 사용 선언 (taglib 지시자)

```jsp
<%@ taglib prefix="c"   uri="http://java.sun.com/jsp/jstl/core" %>
<%@ taglib prefix="fmt" uri="http://java.sun.com/jsp/jstl/fmt" %>
<%@ taglib prefix="fn"  uri="http://java.sun.com/jsp/jstl/functions" %>
```

#### core (c:)

| 태그 | 대응하는 Java | 설명 |
|---|---|---|
| `<c:set var="a" value="1">` | 변수 선언 | 변수 설정 |
| `<c:out value="${a}">` | `System.out.println()` | 화면 출력 |
| `<c:forEach>` | `for` | 반복문 |
| `<c:if test="${조건}">` | `if` | 조건문 |
| `<c:choose>` | `if - else if - else` | 다중 조건문 |
| `<c:redirect url="">` | `sendRedirect()` | 페이지 이동 |

```jsp
<!-- forEach 예시 -->
<c:forEach var="item" items="${list}">
    ${item.name}
</c:forEach>

<!-- if 예시 -->
<c:if test="${score >= 90}">
    <p>A학점</p>
</c:if>
```

#### fmt (fmt:)

| 태그 | 대응하는 Java | 설명 |
|---|---|---|
| `<fmt:formatDate>` | `SimpleDateFormat` | 날짜 형식 변환 |
| `<fmt:formatNumber>` | `DecimalFormat` | 숫자 형식 변환 |

#### fn (fn:)

> `String` 클래스의 주요 메서드를 태그로 제공

```jsp
${fn:length(list)}
${fn:substring(str, 0, 5)}
${fn:trim(str)}
${fn:replace(str, "a", "b")}
```

### MV 구조

> MVC로 가기 전 단계 / HTML과 Java를 분리하는 것에 집중

```
기존 JSP   →  HTML + Java + DB 전부 한 파일
MV 구조    →  화면(HTML/JSP)  +  처리(Java/Servlet) 분리
MVC 구조   →  Model + View + Controller 역할 명확히 분리
              ↓
           Spring MVC → 실무 표준
```

> Controller(Servlet)가 Java 처리를 담당하고
> View(JSP)는 EL/JSTL로 출력만 담당하는 구조로 가는 것이 핵심이다.

### 💡 Note

EL / JSTL은 JSP 안에서 Java 코드를 최대한 걷어내기 위한 도구다.
`<% %>` 대신 `${}` 과 태그 형식을 사용하니 구조가 훨씬 읽기 편해졌다.

MV 구조 실습은 Spring MVC를 배우기 전 JSP에서 Java 코드를 분리하는 연습이었다.
이 흐름을 이해해야 나중에 Front / Back이 완전히 분리되는 MVC 구조가 왜 그렇게 짜여지는지 납득이 된다.

> JSP 학습의 마무리 단계. EL/JSTL → MV → MVC → Spring으로 이어지는 흐름을 염두에 둘 것
