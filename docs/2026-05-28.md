### 1. JSTL

> 자바를 태그 형태로 사용하는 라이브러리  
> `core` : 제어문, 화면이동 / `format` : 날짜·숫자 변환

####  제어문

**반복문**
```jsp
<%-- 기본 for 반복 --%>
<c:forEach var="i" begin="1" end="10" step="1">
    ${i}
</c:forEach>

<%-- 향상된 for (List 순회) --%>
<c:forEach var="vo" items="${list}">
    ${vo.subject}
</c:forEach>
```

**조건문**
```jsp
<%-- 단일 조건 --%>
<c:if test="${i == 10}">출력값</c:if>

<%-- 다중 조건 --%>
<c:choose>
    <c:when test="${i == 10}">출력값</c:when>
    <c:when test="${i == 5}">출력값</c:when>
    <c:otherwise>기본값</c:otherwise>
</c:choose>
```

####  변수 선언 / 화면 이동

```jsp
<%-- 변수 선언 --%>
<c:set var="i" value="10"/>

<%-- 화면 이동 (response.sendRedirect 대체) --%>
<c:redirect url="list.jsp"/>
```

### 2. EL (Expression Language)

> `<%= %>` 를 대체하는 표현식

**스코프별 데이터 출력**
```jsp
${requestScope.키}   <%-- request.getAttribute("키") --%>
<%-- Scope 생략 가능 → ${키} --%>
${sessionScope.키}   <%-- session.getAttribute("키") --%>

```

**연산자**

| 종류 | 설명 | 예시 |
|------|------|------|
| 산술 | `+` 는 덧셈만 (문자열 결합은 +=) | `${a + b}` |
| 비교 | 숫자·날짜·문자 모두 비교 가능 | `${a == b}`, `${a >= b}` |
| 삼항 | 페이지 이전/다음 처리에 활용 | `${조건 ? A : B}` |
| empty | null·빈값 체크 (로그인, 장바구니) | `${empty list}` |

### 3. 데이터 전송 방식

####  GET
- URL 뒤에 데이터 노출 (`?key=value`)
- 사용 태그/방법 : `<a>`, `location.href`, `sendRedirect()`
- 적합한 경우 : 검색어, 페이지 번호, 상세보기 번호

####  POST
- 데이터를 숨겨서 전송
- 사용 태그/방법 : `<form>`, `ajax`, `axios`(Vue), `fetch`
- 적합한 경우 : 데이터량이 많거나 보안이 필요한 경우 (ID/PW)

### 4. 트랜잭션 (Transaction)

> 여러 SQL(INSERT / UPDATE / DELETE)을 하나의 작업 단위로 묶어 처리  
> **모두 성공하면 COMMIT, 하나라도 실패하면 ROLLBACK**

####  핵심 개념

| 용어 | 설명 |
|------|------|
| COMMIT | 모든 작업이 정상 완료 → DB에 영구 반영 |
| ROLLBACK | 작업 중 오류 발생 → 이전 상태로 전체 되돌림 |
| Auto Commit | JDBC 기본값 (SQL 실행마다 자동 commit) |

####  JDBC 트랜잭션 처리 패턴

```java
try {
    getConnection();
 
    // Auto Commit 해제 → 수동 트랜잭션 시작
    conn.setAutoCommit(false);
 
    // SQL 1
    ps = conn.prepareStatement("INSERT INTO ...");
    ps.executeUpdate();
 
    // SQL 2
    ps = conn.prepareStatement("UPDATE ...");
    ps.executeUpdate();
 
    // SQL 3
    ps = conn.prepareStatement("DELETE FROM ...");
    ps.executeUpdate();
 
    // 모두 성공 시 반영
    conn.commit();
 
} catch (Exception e) {
    e.printStackTrace();
    // 하나라도 실패 시 전체 취소 → rollback 자체도 실패할 수 있으므로 중첩 try-catch
    try {
        conn.rollback();
    } catch (Exception e2) { }
 
} finally {
    // AutoCommit 기본값(true) 복구 → 다음 요청에 영향 없도록
    try {
        conn.setAutoCommit(true);
    } catch (Exception e2) { }
    disConnection();
}
```

#### 📌 적용 케이스 (게시판 기준)

| 기능 | 관련 SQL 수 | 트랜잭션 필요 여부 |
|------|------------|------------------|
| 답변 올리기 | 4개 (INSERT + UPDATE × 3) | ✅ 필요 |
| 삭제하기 | 4개 (DELETE + UPDATE × 3) | ✅ 필요 |
| 단순 목록 조회 | 1개 (SELECT) | ❌ 불필요 |

## 💡 Note

### 오늘의 학습 흐름

EL/JSTL을 활용한 CRUD 게시판을 처음부터 끝까지 구현했다.
목록 · 페이지 · 글작성 · 상세보기 · 수정 · 삭제 순으로 진행했고,
이전과 달리 Java 코드를 JSP 파일에서 최대한 분리하는 방식으로 작업했다.

마지막으로 답글 기능을 추가했는데, 이 과정에서 트랜잭션 개념이 실제로 적용됐다.
답글 등록 시 여러 SQL이 순차적으로 수행되기 때문에
하나라도 실패하면 전체를 취소하는 **All or Nothing** 원칙이 필요했다.
`try-catch` 구조로 이를 직접 구현했고, catch 블록 안에 중첩 `try-catch`를 작성하여
오류 발생 시 rollback이 안전하게 동작하도록 처리했다.

### 오늘의 회고

흐름 파악 위주로 반복하며 내실을 다지다 보니,
어떤 상황에서 어떤 코드가 와야 하는지 감이 잡히기 시작했다.

- DAO 패턴의 전체 흐름(연결 → 쿼리 → 반환)을 스스로 구성할 수 있게 됐다.
- DBCP 설정을 통해 Connection Pool을 직접 코드로 작성할 수 있다.
- SQL 쿼리를 좀 더 정교하게 짜는 연습이 필요하다는 것도 인식했다.
