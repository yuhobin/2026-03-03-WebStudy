### XML (eXtensible Markup Language)

HTML처럼 태그 기반이지만, 태그를 직접 정의해서 쓰는 **사용자 정의 마크업 언어**다.
데이터를 구조적으로 표현하는 데 특화되어 있으며, Spring과 MyBatis의 설정 파일 포맷으로 사용된다.

#### 핵심 문법 규칙

- 루트 태그가 반드시 하나 존재해야 한다 (트리 구조)
- 여는 태그와 닫는 태그가 반드시 일치해야 하며, 내용이 없으면 `<태그/>`로 표현
- 대소문자 구분
- 속성값은 반드시 따옴표로 감싼다 (`속성="값"`)
- 태그명과 속성명은 반드시 문자로 시작해야 한다

### DTD (Document Type Definition)

XML 문서의 **구조와 규칙을 정의하는 명세서**다.
어떤 태그를 사용할 수 있는지, 어떤 속성을 가질 수 있는지 등을 미리 정해두어 XML 문서의 유효성을 검사하는 역할을 한다.

```xml
<!DOCTYPE configuration
  PUBLIC "-//mybatis.org//DTD Config 3.0//EN"
  "https://mybatis.org/dtd/mybatis-3-config.dtd">
```

위처럼 MyBatis 설정 파일 상단에 DTD를 선언하면, `<configuration>`, `<environments>`, `<mapper>` 같은 태그들이 MyBatis가 정의한 규칙에 맞게 작성되었는지 검증된다. HTML의 DOCTYPE 선언과 같은 개념이다.

#### XML 파싱 방식

| 방식 | 특징 |
|------|------|
| SAX | 한 줄씩 읽어서 처리. 메모리 효율적. MyBatis, Spring이 내부적으로 사용 |
| DOM | 문서 전체를 메모리에 올려서 트리로 제어. 자유롭게 탐색 가능하지만 무겁다 |

실제로 라이브러리(MyBatis, Spring)를 사용하면 파싱은 라이브러리가 알아서 처리한다.

#### XML vs JSON

XML은 구조가 엄격하고 태그가 중복되어 데이터가 무겁다는 단점이 있다. 현재는 가볍고 파싱이 빠른 **JSON이 API 통신에서 XML을 대체**하고 있으며, XML은 주로 설정 파일이나 B2B 데이터 교환 용도로 남아 있다.

### MVC 구조에서 XML의 역할

Spring과 MyBatis에서 XML은 주로 **환경 설정과 SQL 관리** 역할을 담당한다.

| 프레임워크 | XML 역할 |
|-----------|---------|
| Spring | `web.xml` - 서블릿 초기화 및 URL 매핑 설정 |
| MyBatis | `mybatis-config.xml` - DB 연결 정보, VO 등록 |
| MyBatis | `mapper.xml` - SQL 쿼리 관리 (PreparedStatement, ResultSet 역할) |

### Controller (Servlet)

#### 서블릿 동작 흐름

```
브라우저 요청
    ↓
init()  → web.xml 기반 환경설정 (서버 시작 시 1회)
    ↓
service() → 요청 방식에 따라 분기
    ├── doGet()  : URL 직접 입력, <a>, location.href, sendRedirect
    └── doPost() : <form>, Ajax (axios/fetch) - header에 데이터 첨부
    ↓
destroy() → 메모리 해제 (서버 종료 시)
```

`doGet()`과 `doPost()`의 처리 방식이 동일한 경우, 둘을 하나의 `service()` 메서드로 합쳐서 Controller로 사용한다.

#### MVC 역할 분리

```
브라우저 (손님)
    ↓ 요청
Controller - Servlet (서빙 담당)
    ↓ 호출
Model - Java (비즈니스 로직, DB 처리)
    ↓ 결과 반환
Controller
    ↓ 데이터 전달
View - JSP (화면 출력)
```

#### 데이터 전달 방식

| 범위 | 방식 | 용도 |
|------|------|------|
| 요청 단위 | `request.setAttribute()` | JSP 한 페이지에만 전달 |
| 세션 단위 | `session.setAttribute()` | 여러 JSP에서 공통으로 사용 |

Controller는 Model에서 받은 처리 결과를 request나 session에 담아 JSP로 넘겨주는 **중간 다리 역할**을 한다.

## 💡 Note
### 오늘의 학습 흐름
XML의 역할과 문법을 학습하고 MyBatis 설정 파일을 직접 작성해봤다.
XML이 Spring과 MyBatis에서 환경설정과 SQL 관리를 어떻게 담당하는지 구조적으로 파악했고,
DTD가 XML 문서의 유효성을 어떻게 검증하는지도 함께 다뤘다.
이후 Controller 클래스를 직접 만들어 MVC 구조를 실제로 구현해봤다.
JSP에 섞여 있던 Java 코드를 Controller와 Model로 분리해내면서
브라우저 요청 → Controller → Model → JSP로 이어지는 흐름을 몸으로 익혔다.

### 오늘의 회고
MVC 구조 자체보다 **흐름을 이해하는 것**에 집중한 하루였다.
- XML이 단순한 설정 파일이 아니라 프레임워크가 동작하는 기반이라는 걸 이해했다.
- Controller가 중심을 잡고 Model과 View를 연결하는 역할이라는 게 명확해졌다.
- 지금 배우는 Servlet 기반 MVC가 Spring의 축약된 구조를 이해하는 데 직결된다는 것을 인식했다.
- 실무에서 MVC가 표준처럼 쓰이는 이유를 구조를 직접 짜보면서 납득할 수 있었다.
