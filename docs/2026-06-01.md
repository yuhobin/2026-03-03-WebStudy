### 1. MyBatis란?

- SQL을 XML 파일에 작성하면 MyBatis가 자동으로 DB 연결 / 실행 / 결과값 처리 / 닫기를 처리해주는 라이브러리
- JSP 기반 웹 사이트에서는 주로 XML 방식 사용, Spring Boot에서는 Annotation 방식 사용

---

### 2. JDBC와의 차이점

| 항목 | JDBC | MyBatis |
|------|------|---------|
| DB 연결 코드 | DAO마다 직접 작성 | Config.xml 한 곳에서 관리 |
| SQL 문장 | DAO 코드 안에 작성 | mapper.xml에 분리 작성 |
| ResultSet 처리 | 직접 반복문으로 처리 | 자동으로 VO에 매핑 |
| 반복 코드 | 많음 | 거의 없음 |

MyBatis 적용 후 DAO에서 직접 작성하던 DB 연결 코드와 SQL 문장이 사라지고,
XML을 파싱해서 처리하는 코드로 대체된다.

---

### 3. 동작 구조

```
Config.xml
    └── DB 연결 정보 (한 개만 설정)
    └── typeAliases (VO 등록)
    └── mapper.xml 경로 등록

mapper.xml (테이블당 1개 생성)
    └── SQL 문장 작성
    └── resultType : 결과값을 담을 VO 지정
    └── parameterType : SQL에 전달할 값 지정

DAO
    └── SqlSessionFactory : Config.xml 파싱 + SqlSession 생성
    └── SqlSession : SQL 실행 담당 (JDBC의 PreparedStatement + ResultSet 역할)
```

### 4. 핵심 설정 파일

#### Config.xml
MyBatis 전체 설정 파일. **태그 순서가 반드시 지켜져야 한다.**

```xml
<configuration>
    <typeAliases>   <!-- VO 클래스 등록 -->
        <typeAlias type="com.sist.vo.BoardVO" alias="BoardVO"/>
    </typeAliases>

    <environments default="development">
        <environment id="development">
            <transactionManager type="JDBC"/>
            <dataSource type="POOLED">
                <property name="driver" value="oracle.jdbc.driver.OracleDriver"/>
                <property name="url" value="jdbc:oracle:thin:@localhost:1521:XE"/>
                <property name="username" value="hr"/>
                <property name="password" value="happy"/>
            </dataSource>
        </environment>
    </environments>

    <mappers>   <!-- mapper.xml 경로 등록 -->
        <mapper resource="com/sist/dao/board-mapper.xml"/>
    </mappers>
</configuration>
```

#### mapper.xml
SQL 문장을 작성하는 파일. 테이블당 1개 생성.

```xml
<mapper namespace="com.sist.dao.board-mapper">
    <select id="listData" resultType="BoardVO" parameterType="int">
        SELECT no, subject, name FROM board
        WHERE no = #{no}
    </select>
</mapper>
```

---

### 5. mapper.xml 주요 태그

| 태그 | 용도 |
|------|------|
| `<select>` | SELECT 쿼리 |
| `<insert>` | INSERT 쿼리 |
| `<update>` | UPDATE 쿼리 |
| `<delete>` | DELETE 쿼리 |
| `<sql>` | 공통으로 반복되는 SQL 조각 (include로 재사용) |
| `<resultMap>` | 조인 시 VO+VO 매핑할 때 사용 |
| `<parameterMap>` | PROCEDURE 사용 시 |

#### #{} 와 ${} 차이

| 표현식 | 특징 | 사용 예 |
|--------|------|---------|
| `#{}` | `''` 포함해서 값 처리 (안전) | 일반 값, WHERE 조건 |
| `${}` | `''` 없이 그대로 처리 | 테이블명, 컬럼명 |

#### parameterType 정리
- 값이 1개 → `int`, `String` 등 기본형
- 값이 여러 개 → `VO` 클래스 사용
- VO에 없는 변수가 여러 개 → `Map` 사용

---

### 6. 장단점

#### 장점
- SQL을 개발자가 직접 제어 → 성능 최적화(튜닝) 가능
- 복잡한 SQL 문장도 자유롭게 작성 가능
- 반복적인 JDBC 코드 제거

#### 단점
- SQL을 직접 작성해야 함 (JPA는 자동 생성)
- DB 변경 시 SQL 수정 필요
- 순수 객체지향 ORM으로는 JPA보다 약함

## 💡 Note

####  DB 테이블 컬럼명 오타 주의

데이터를 못 불러와 콘솔을 확인해보니 `'yyyy-MM-dd'` 형식의 날짜를 못 불러온다는 메시지 확인.
DB 연결 코드와 쿼리문을 검토했지만 코드상 문제가 없어 보였고 서버 클린도 해봤으나 해결되지 않았다.
마지막으로 Oracle에서 직접 테이블을 확인한 결과 `regdate` 가 `redgate` 로 오타가 난 상태로 생성된 것을 발견.

```sql
-- 테이블 생성 시 오타
redgate DATE DEFAULT SYSDATE  -- ← regdate가 되어야 했음

-- 결국 쿼리도 오타에 맞춰야 동작
TO_CHAR(redgate, 'yyyy-MM-dd') as dbday
```

> **배운점:** DB에서 테이블을 생성할 때 컬럼명에 오타가 나면, 이후 쿼리문의 컬럼명과 불일치가 발생해
> 데이터를 아예 못 불러오는 상황이 생긴다. 테이블 설계 시 컬럼명을 신중하게 작성해야 한다.

####  `""` 안의 공백은 문자열의 일부

콘솔에 에러도 안 찍히고 StackTrace 페이지도 나타나지 않은 채 흰 화면으로 데이터를 못 불러오는 상황.
DB 연결부터 역으로 추적하다가 JSP의 `<c:forEach>` 에서 문제를 발견.

```jsp
<!-- ❌ items="" 안에 공백 포함 -->
<c:forEach var="vo" items="${list} ">

<!-- ✅ 공백 제거 -->
<c:forEach var="vo" items="${list}">
```

> **배운점:** `""` 안에 공백이 있으면 공백까지 문자열의 일부로 포함되어 전혀 다른 문자열로 인식된다.
> 에러 메시지조차 안 뜨는 경우도 있으니 데이터가 안 보일 때는 EL 표현식 주변 공백도 확인할 것.
