## 2. 터미널 환경 구성

초기 설치 직후에는 GUI 터미널 앱이 정상적으로 실행되지 않았다.  
`Ctrl + Alt + F3` 단축키로 CLI 콘솔(TTY)에 진입한 뒤 아래 과정을 거쳐 터미널을 사용할 수 있도록 설정했다.

**① sudo 권한 부여**

```bash
sudo su -                          # root로 전환
nano /etc/sudoers
```

`sudoers` 파일에서 아래 줄 바로 밑에 동일한 형식으로 계정을 추가한다.

```
root    ALL=(ALL:ALL) ALL
sist    ALL=(ALL:ALL) ALL          # sist : 사용 계정명
```

저장 후 `exit`으로 root에서 로그아웃한다.

**② 로케일(locale) 설정**

```bash
sudo nano /etc/default/locale
```

`LANG` 값 뒤에 `.UTF-8`을 추가해 한글·특수문자 인코딩 문제를 방지한다.

```
LANG=en_US.UTF-8
```

**③ 터미널 패키지 재설치**

```bash
sudo apt purge gnome-terminal -y
sudo apt install gnome-terminal -y
```

터미널이 깨져 있거나 실행이 안 될 때 purge 후 재설치로 해결한다.

**④ 재부팅 후 확인**

```bash
reboot
```

재부팅 이후 GUI 터미널이 정상 실행되는지 확인한다.

## 3. Java JDK 17 설치

```bash
sudo apt install openjdk-17-jdk -y    # JDK 17 설치
java -version                          # 설치 확인
ls -al /usr/lib/jvm/                   # 설치 경로 확인
```

설치된 JDK 경로(`/usr/lib/jvm/java-17-openjdk-amd64`)를 확인한 뒤  
`~/.bashrc`에 환경 변수를 등록한다.

```bash
nano ~/.bashrc
```

파일 하단에 아래 내용을 추가한다.

```bash
export JAVA_HOME=/usr/lib/jvm/java-17-openjdk-amd64
export PATH=$PATH:$JAVA_HOME/bin
```

저장 후 변경 사항을 즉시 반영한다.

```bash
source ~/.bashrc
java -version                          # 환경 변수 적용 최종 확인
```

> `ls -al` 명령어로 디렉토리 내 파일 목록 및 권한 정보를 수시로 확인할 수 있다.

## 4. Apache Tomcat 11 설치

[tomcat.apache.org](https://tomcat.apache.org) 에 접속해  
Tomcat 11 → **Core** 항목의 `.tar.gz` 링크를 복사한다.

```bash
# 복사한 링크를 붙여넣어 다운로드
wget https://downloads.apache.org/tomcat/tomcat-11/v11.x.x/bin/apache-tomcat-11.x.x.tar.gz

# 압축 해제
tar -xvzf apache-tomcat-11.x.x.tar.gz

# 적절한 위치로 이동
sudo mv apache-tomcat-11.x.x /opt/tomcat

# 실행 권한 부여
sudo chmod +x /opt/tomcat/bin/*.sh
```

서버 기동 및 종료 확인:

```bash
/opt/tomcat/bin/startup.sh     # 서버 시작
/opt/tomcat/bin/shutdown.sh    # 서버 종료
```

## 5. WAR 파일 배포 및 실행 확인

**① Eclipse에서 WAR 파일 내보내기**

```
프로젝트 우클릭 → Export → WAR file → 경로 지정 → Finish
```

완성된 WAR 파일을 이메일로 전송한 뒤 Ubuntu에서 수신한다.

**② 배포 디렉토리 생성 및 파일 이동**

```bash
mkdir -p ~/site                                      # 작업 디렉토리 생성
mv [파일명].war ~/site/                              # WAR 파일 이동
cp ~/site/[파일명].war /opt/tomcat/webapps/          # webapps에 복사
```

**③ Tomcat 기동 및 자동 압축 해제 확인**

```bash
/opt/tomcat/bin/startup.sh
tail -f /opt/tomcat/logs/catalina.out    # 실행 로그 실시간 확인
```

Tomcat이 기동되면 `webapps/` 안에 WAR가 자동으로 압축 해제된다.  
브라우저에서 `http://[서버IP]:8080/[프로젝트명]` 으로 접속해 목록 페이지가 정상 출력되는지 확인한다.

> ✅ Controller 정상 동작 및 맛집 게시판 목록 출력 확인 완료

## 💡 Note

### ❌ Config 파일 오타 → 데이터 미조회

`config.xml`의 `dataSource type` 값을 `sist` 대신 `sisit`로 잘못 입력해 DB 연결이 되지 않았다.

```xml
<!-- ❌ -->
<dataSource type="sisit">

<!-- ✅ -->
<dataSource type="sist">
```

### ❌ mapper.xml SQL 오타 → 데이터 미조회

`FROM`을 `FORM`으로 잘못 입력해 쿼리가 실행되지 않았다.

```sql
-- ❌
SELECT * FORM restaurant

-- ✅
SELECT * FROM restaurant
```

> 💡 데이터가 조회되지 않는다면 `DAO`, `mapper.xml`, `config.xml` 순으로 확인할 것

---

### ❌ 페이징 처리 대소문자 오타

`totalPage`를 `totalpage`로 작성해 변수를 찾지 못했다.

```java
// ❌
int total = totalpage;

// ✅
int total = totalPage;
```

> 💡 Java는 대소문자를 엄격히 구분하므로 camelCase 규칙을 일관되게 유지할 것
