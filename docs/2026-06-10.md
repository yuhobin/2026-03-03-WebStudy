## 1. JavaScript 내장 객체 (Built-in Objects)

JavaScript는 별도의 import 없이 바로 사용할 수 있는 내장 객체들을 제공한다.  
Java의 `java.lang` 패키지가 자동 임포트되는 것과 같은 개념이다.

---

### 1) Number

| 메서드 | 설명 |
|--------|------|
| `parseInt(str)` | 문자열 → 정수 변환. 숫자로 시작하지 않으면 `NaN` 반환 |
| `parseFloat(str)` | 문자열 → 실수 변환 |
| `num.toLocaleString()` | 천 단위 콤마 포맷 (`1000000` → `"1,000,000"`) |
| `num.toFixed(n)` | 소수점 n자리 고정 |

> 입력값 검증 시 `isNaN()` 과 함께 사용하는 패턴이 많다.

---

### 2) String

문자열 인덱스는 Java와 동일하게 **0번부터** 시작한다.

| 메서드 | 설명 |
|--------|------|
| `str.length` | 문자 수 (프로퍼티, `()` 없음) |
| `str.indexOf(s)` / `lastIndexOf(s)` | 앞/뒤에서 위치 찾기, 없으면 `-1` |
| `str.includes(s)` | 포함 여부 `true/false` |
| `str.startsWith(s)` / `endsWith(s)` | 시작/끝 문자 확인 |
| `str.replace(a, b)` | 첫 번째 일치 문자 교체 |
| `str.replaceAll(a, b)` | 모든 일치 문자 교체 |
| `str.split(sep)` | 구분자로 잘라 배열 반환 |
| `str.substring(start, end)` | 인덱스 범위로 자르기 (end **미포함**) |
| `str.trim()` | 좌우 공백 제거 |

> **`substring` vs Oracle `substr` 비교**
> ```
> JavaScript : substring(startIndex, endIndex)  → endIndex 미포함
> Oracle      : substr(start, count)             → count는 개수
> ```

---

### 3) Array

| 메서드 | 설명 | 원본 변경 |
|--------|------|-----------|
| `push(val)` / `pop()` | 마지막 추가 / 제거 | O |
| `shift()` / `unshift(val)` | 첫 번째 제거 / 추가 | O |
| `slice(start, end)` | 범위 잘라 새 배열 반환 | X |
| `find(fn)` | 조건 만족하는 첫 번째 요소 반환 | X |
| `filter(fn)` | 조건 만족하는 모든 요소 배열 반환 | X |
| `map(fn)` | 각 요소 변환한 새 배열 반환 | X |
| `forEach(fn)` | 각 요소 순회 (반환값 없음) | X |
| `length` | 배열 길이 (프로퍼티) | - |

---

### 4) Date

```javascript
const today = new Date();

today.getFullYear()   // 연도
today.getMonth()      // 월 (0~11, 실제 월은 +1 필요)
today.getDate()       // 일
today.getDay()        // 요일 (0=일요일 ~ 6=토요일)
today.getHours()      // 시
today.getMinutes()    // 분
```

> `getMonth()`는 0부터 시작하므로 화면에 표시할 때 반드시 `+1` 해야 한다.  
> 달력 UI가 필요한 경우 **FullCalendar** 라이브러리를 활용한다.

---

### 5) Math

| 메서드 | 설명 |
|--------|------|
| `Math.round(n)` | 반올림 |
| `Math.ceil(n)` | 올림 |
| `Math.floor(n)` | 내림 |
| `Math.random()` | 0 이상 1 미만 난수 |
| `Math.abs(n)` | 절댓값 |

## 2. BOM (Browser Object Model)

BOM은 브라우저 자체를 제어하는 객체 모음이다.  
Java에는 없는 개념으로, **브라우저 환경에서만** 사용 가능하다.

```
window (최상위)
  ├── location   : URL / 페이지 이동
  ├── history    : 방문 기록 제어
  └── document   : HTML 문서 제어 (DOM의 진입점)
```

| 사용법 | 설명 | Java/JSP 비교 |
|--------|------|---------------|
| `window.open(url, name, option)` | 새 창 열기 | - |
| `window.close()` / `self.close()` | 현재 창 닫기 | - |
| `window.opener` | 자신을 열어준 부모 창 참조 | - |
| `location.href = "url"` | 페이지 이동 | `sendRedirect()` |
| `location.reload()` | 새로고침 | - |
| `history.back()` / `history.go(-1)` | 이전 페이지 이동 | - |
| `alert()` / `confirm()` / `prompt()` | 대화상자 | - |

## 3. jQuery DOM 조작

jQuery는 JavaScript의 DOM API를 **간결하게 래핑한 라이브러리**이다.  
`$("CSS선택자")` 로 요소를 선택한 뒤 체이닝(`.메서드().메서드()`)으로 조작한다.

```
Vanilla JS                          jQuery
document.querySelector("선택자")  →  $("선택자")
```

---

### 1) 텍스트 / HTML 조작

| 목적 | Vanilla JS | jQuery |
|------|-----------|--------|
| 텍스트만 변경 | `el.textContent = "값"` | `$("선택자").text("값")` |
| HTML 포함 변경 | `el.innerHTML = "<b>값</b>"` | `$("선택자").html("<b>값</b>")` |

> 사용자 입력값을 출력할 때는 반드시 `text()`를 사용한다.  
> `html()`에 외부 입력을 넣으면 XSS(크로스 사이트 스크립팅) 취약점이 생긴다.

---

### 2) 스타일 조작

| 방식 | 코드 |
|------|------|
| Vanilla JS | `el.style.backgroundColor = "yellow"` |
| jQuery 단일 | `$("#btn").css("color", "red")` |
| jQuery 다중 (권장) | `$("#btn").css({ "color": "red", "backgroundColor": "yellow" })` |

> CSS의 `background-color`는 JS/jQuery에서 `backgroundColor` (camelCase) 로 작성한다.

---

### 3) 속성 조작

| 목적 | Vanilla JS | jQuery |
|------|-----------|--------|
| 속성 읽기/쓰기 | `img.src` / `img.src = "경로"` | `$("img").attr("src")` / `attr("src", "경로")` |
| input 값 읽기/쓰기 | `input.value` / `input.value = "값"` | `$("input").val()` / `val("값")` |
| class 추가/제거 | `el.classList.add/remove("cls")` | `$("el").addClass/removeClass("cls")` |

---

### 4) getter / setter 패턴

jQuery 메서드는 **인자 유무**로 읽기(getter)와 쓰기(setter)를 구분한다.

| 메서드 | getter (읽기) | setter (쓰기) |
|--------|-------------|-------------|
| `text()` | `text()` | `text("값")` |
| `html()` | `html()` | `html("값")` |
| `val()` | `val()` | `val("값")` |
| `attr()` | `attr("속성명")` | `attr("속성명", "값")` |
| `css()` | `css("속성명")` | `css("속성명", "값")` |

## NOTE

### 프론트엔드 개발 흐름

프론트엔드 코드를 작성할 때는 아래 4단계 흐름을 기준으로 사고하면 좋다.

```
① 선택  (누구를?)   CSS 선택자로 대상 요소를 지정한다.
② 논리  (어떻게?)   JavaScript function으로 데이터를 가공하거나 조건을 처리한다.
③ 반영  (어디에?)   DOM API / jQuery로 처리 결과를 화면에 삽입하거나 갱신한다.
④ 반응  (언제?)     이벤트 리스너로 사용자 행동(클릭, 입력 등)에 묶어준다.
```

**한 줄 요약 : 누구를 → 어떻게 가공해서 → 어디에 넣을지 → 언제 실행할지**

막히는 부분이 생겼을 때 이 흐름의 어느 단계인지 먼저 파악하면 빠르게 원인을 좁힐 수 있다.

### 오늘 실습 & 배운 점

오늘은 JavaScript 내장 객체와 BOM을 활용하여 우편번호 검색 기능을 구현했다.  
`window.open()`으로 팝업 창을 띄우고, DB에서 조회한 우편번호 목록을 JSP(`c:forEach`)로 렌더링한 뒤, 항목 클릭 시 `opener`를 통해 부모 창의 form 필드에 우편번호와 주소를 자동 입력하고 팝업을 닫는 흐름을 직접 구현했다.

처음에는 jQuery의 `$()` 와 JSP EL의 `${}` 괄호 혼용, `"` 안에 `'`를 섞어 쓰는 따옴표 패턴, 선택자 대소문자 불일치(콘솔에 에러가 찍히지 않아 찾기 어려웠다) 등 여러 부분에서 막혔지만, 동작 흐름을 역추적하며 하나씩 수정하다 보니 이제는 에러를 마주쳐도 어느 단계에서 문제가 생겼는지 판단하는 감각이 생겼다.
