### 1. Ajax란?

**Ajax(Asynchronous JavaScript and XML)** 는 페이지 전체를 새로 불러오지 않고, **필요한 데이터만 서버에 요청해서 화면 일부만 갱신**하는 방식이다.

이름에 XML이 들어가 있지만 현재는 XML보다 **JSON** 형식의 데이터를 주고받는 것이 일반적이다.

---

### 2. Ajax 동작 원리

#### 1) 전통적인 요청 방식 vs Ajax

| 구분 | 전통 방식 | Ajax |
|------|----------|------|
| 요청 단위 | 페이지 전체 | 데이터만 |
| 화면 처리 | 브라우저가 전체 다시 렌더링 | JS가 필요한 부분만 DOM 갱신 |
| 화면 깜빡임 | 있음 | 없음 |
| 사용자 경험 | 요청마다 페이지 이동 | 자연스러운 부분 갱신 |
| JSP 비교 | `sendRedirect()` / `forward()` | `$.ajax()` |

검색창 자동완성, 무한 스크롤, 페이징 처리 등 현재 대부분의 웹 기능이 Ajax 방식이다.

---

#### 2) 비동기(Asynchronous)란?

Ajax의 핵심 개념이다. 일반 코드는 위에서 아래로 순서대로 실행되지만, Ajax 요청은 **서버 응답을 기다리는 동안 다음 코드가 먼저 실행된다.**

```
[동기]  요청 → (대기) → 응답 → 다음 코드 실행
[비동기] 요청 → 다음 코드 실행 → (응답 오면) → callback 함수 자동 호출
```

응답이 언제 올지 모르기 때문에, **"응답이 오면 이 함수를 실행해"** 라고 미리 등록해두는 방식이 콜백(callback)이다.  
jQuery Ajax의 `success: function(data) { }` 가 바로 이 콜백이다.

#### 3) readyState / status

XMLHttpRequest가 서버와 통신하는 단계를 나타낸다.  
jQuery `$.ajax()`를 쓰면 이 값들을 직접 다루지 않아도 되지만, 내부 흐름을 이해하는 데 중요하다.

**readyState : 통신 진행 단계**

| 값 | 의미 |
|----|------|
| 0 | 객체 생성, 서버 연결 준비 |
| 1 | `open()` 호출, 서버 연결 |
| 2 | 서버 연결 완료 |
| 3 | `send()` 호출, 데이터 전송 준비 |
| 4 | 데이터 전송 완료 → 응답 읽기 가능 |

**status : 서버 처리 결과**

| 값 | 의미 |
|----|------|
| 200 | 정상 처리 (`success`) |
| 404 | 요청한 URL 없음 |
| 500 | 서버 내부 오류 |

실제로 응답 데이터를 읽을 수 있는 조건은 `readyState === 4 && status === 200` 일 때다.

### 3. XMLHttpRequest : Ajax의 내부 구조

브라우저에 내장된 객체로, jQuery `$.ajax()`가 내부적으로 사용하는 핵심 객체다.  
직접 작성하면 요청 한 번에 아래 단계를 모두 코드로 구현해야 한다.

```
1. XMLHttpRequest 객체 생성
2. 요청 방식(GET/POST) 지정
3. 파라미터 처리 (?key=value)
4. open() : 서버 연결 설정
5. setRequestHeader() : Content-Type 지정
6. onreadystatechange : 콜백 함수 등록
7. send() : 데이터 전송
8. 응답 도착 시 responseText / responseXML 으로 데이터 읽기
```

이 과정 전체를 jQuery가 `$.ajax({})` 한 블록으로 추상화해준다.  
풀어서 직접 작성해보는 이유는, 축약된 라이브러리 코드 뒤에서 **어떤 흐름이 작동하는지** 파악하기 위해서다.

### 4. jQuery Ajax : 코드 간결화

#### 1) $.ajax() 기본 구조

```javascript
$.ajax({
    type    : 'POST',             // 요청 방식 GET / POST
    url     : 'list_ajax.do',     // 요청 보낼 서버 주소
    data    : { "page" : page },  // 서버에 보낼 파라미터
    success : function(json) {    // 응답 성공 시 자동 호출 (콜백)
        json = JSON.parse(json);  // 문자열 → JSON 객체로 변환
        // DOM 갱신
    },
    error   : function() {        // 요청 실패 시 처리
        alert("오류 발생");
    }
});
```

XMLHttpRequest로 8단계를 직접 구현하던 것을 옵션 객체 하나로 처리한다.

---

#### 2) 반복 요청은 함수로 묶기

페이징처럼 같은 요청을 여러 버튼에서 호출할 경우, Ajax 요청을 하나의 함수로 묶고 각 버튼은 그 함수를 호출하는 방식으로 중복을 제거한다.

```javascript
// 반복 제거 전
function prev(page) { /* ajax 코드 전체 */ }
function next(page) { /* ajax 코드 전체 */ }
function change(page) { /* ajax 코드 전체 */ }

// 반복 제거 후
function prev(page)   { dataRecv(page); }
function next(page)   { dataRecv(page); }
function change(page) { dataRecv(page); }

function dataRecv(page) {
    $.ajax({
        type    : 'post',
        url     : 'list_ajax.do',
        data    : { "page" : page },
        success : function(json) {
            json = JSON.parse(json);
            foodPrint(json);  // 화면 갱신 함수 호출
        }
    });
}
```

Ajax 요청 자체는 `dataRecv()` 하나에만 작성하고, 나머지 함수들은 그것을 호출하기만 한다.  
기능이 많아질수록 이런 **메서드화(함수 분리)** 습관이 코드 가독성과 유지보수에 직결된다.

### 5. Vue + Axios : 참고

Vue는 화면 구성과 데이터를 연결하는 프론트엔드 프레임워크이고,  
Axios는 Ajax 요청을 처리하는 라이브러리다. jQuery의 `$.ajax()`와 역할이 같다.

| 구분 | jQuery Ajax | Vue + Axios |
|------|-------------|-------------|
| 요청 방식 | `$.ajax({})` | `axios.get()` / `axios.post()` |
| 화면 갱신 | DOM을 직접 조작 | 데이터만 바꾸면 화면이 자동 갱신 |
| 코드 구조 | 절차적 | 선언적 (데이터 중심) |

Vue는 데이터가 바뀌면 연결된 화면이 자동으로 따라 바뀌는 구조라,  
DOM을 직접 건드릴 필요가 없다는 점이 jQuery Ajax와의 가장 큰 차이다.  
현 단계에서는 Ajax의 흐름을 이해하는 것이 우선이며, Vue는 이후 학습 예정이다.

## 💡 Note

#### Ajax 처리 흐름 요약

```
① 사용자 행동 (버튼 클릭 등)
② $.ajax() 로 서버에 비동기 요청 전송
③ 서버(Controller) 에서 DB 조회 후 JSON 데이터 반환
④ success 콜백 함수 자동 호출 → JSON.parse() 로 객체 변환
⑤ DOM 조작으로 화면 일부 갱신 (페이지 이동 없음)
```

#### 오늘 실습

- Ajax 내부 동작을 이해하기 위해 XMLHttpRequest를 직접 풀어서 작성하고, 버튼 클릭 시 화면 전환 및 이미지 출력을 구현했다.
- jQuery `$.ajax()`를 사용해 맛집 목록을 불러오는 기능을 구현하고, 동일한 결과를 Vue + Axios로도 구현해 비교했다.
- 페이징 기능을 Ajax로 구현하면서 반복되는 요청 코드를 `dataRecv(page)` 함수로 묶어 중복을 제거했다.
- 맛집 지도에 카카오 지도 키를 활용한 지도를 삽입하여 맛집지도를 구현해보았다. 

#### 배운 점

구현할 기능이 많아지면서 코드가 길어질수록, 라이브러리로 코드를 축약하고 반복되는 로직은 함수로 묶는 습관이 얼마나 중요한지 체감했다. 

한편으로는 축약된 코드만 보면 흐름을 놓치기 쉬워서, 일부러 XMLHttpRequest를 직접 풀어 작성하며 내부 동작을 파악하는 과정을 거쳤다. 

이 방식이 이후 Spring처럼 많은 것이 자동화된 환경을 학습할 때 코드 뒤의 흐름을 읽는 데 도움이 될 것이라고 한다. 

새로운 코드 구조를 만나 에러가 나더라도, 코드를 다시 들여다보고 흐름을 역추적하며 복기하는 것이 구조를 익히는 가장 확실한 방법임을 다시 확인했다. 

기능이 늘어날수록 세부 문법보다 **프로그램이 작동하는 흐름을 놓치지 않는 것** 이 가장 중요하다고 생각한다.
