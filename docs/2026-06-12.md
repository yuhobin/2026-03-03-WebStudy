### 1. Git 터미널 연동 (Windows)

#### 1) 최초 등록 및 원격 저장소 연결

프로젝트 폴더를 Git으로 관리하고 GitHub에 최초 연결하는 과정이다.

```bash
# 1. 프로젝트 폴더로 이동
cd C:/webDev/webStudy/JSPMVCTotalProject

# 2. Git 초기화
git init

# 3. 파일 스테이징
git add .
# LF/CRLF 관련 warning이 뜨면 한 번 더 실행
git add .

# 4. 기본 브랜치 이름 설정
git branch -M main

# 5. 첫 커밋
git commit -m "first"

# 6. 원격 저장소 연결
git remote add origin https://github.com/yuhobin/JSPMVCTotalProject.git

# 7. 최초 푸시 (처음 한 번만 --force 사용)
git push -u origin main --force
```

> **LF/CRLF warning이 뜨는 이유**  
> Windows(CRLF)와 Linux(LF)의 줄바꿈 방식 차이로 인해 발생하는 경고다.  
> 오류가 아니므로 `git add .` 를 한 번 더 실행하면 된다.

---

#### 2) 이후 커밋 및 푸시

최초 등록 이후 변경사항을 올릴 때는 아래 3단계만 반복한다.

```bash
git add .
git commit -m "커밋 메시지"
git push -u origin main
```

---

#### 3) 주의사항

> ⚠️ **터미널로 Git에 올린 폴더는 Eclipse의 Share Project로 다시 올리면 충돌이 발생한다.**  
> 터미널 방식과 IDE 방식 중 하나만 사용해야 하며, 혼용 시 GitHub 저장소를 삭제하고 재생성해야 할 수 있다.

### 3. Ubuntu에서 Tomcat 서버 설정 및 실행

#### 1) classes 파일 경로 이동

GitHub에 클론한 프로젝트는 컴파일된 `.class` 파일이 `build/classes`에 위치해 있다.  
Tomcat이 서블릿을 인식하려면 `WEB-INF/classes` 아래에 있어야 하므로 복사가 필요하다.

```bash
# build/classes 를 WEB-INF 하위로 복사
sudo cp -r classes ~/JSPMVCEmpProject/src/main/webapp/WEB-INF
```

> **왜 이 작업이 필요한가?**  
> Eclipse에서 작업할 때는 IDE가 자동으로 `build/classes`를 참조하지만,  
> Ubuntu에서 Tomcat이 직접 프로젝트를 실행할 때는 `WEB-INF/classes`에 `.class` 파일이 없으면  
> `.do` 요청(서블릿)을 처리하지 못해 404 또는 500 에러가 발생한다.

---

#### 2) server.xml 설정 (Context 추가)

Tomcat에 프로젝트 경로를 등록해야 브라우저에서 접근할 수 있다.

```bash
# Tomcat conf 폴더로 이동
cd /opt/tomcat/conf        # Tomcat 설치 경로에 따라 다를 수 있음

# server.xml 편집
sudo nano server.xml
```

파일 맨 아래 `</Host>` 태그 바로 위에 `<Context>` 태그를 추가한다.

```xml
<Context docBase="/home/sist/JSPMVCEmpProject/src/main/webapp"
         path="/web"
         reloadable="true"
         workDir="work"/>
```

| 속성 | 설명 |
|---|---|
| `docBase` | 프로젝트 webapp 폴더의 절대 경로 (`pwd`로 복사해둔 경로 활용) |
| `path` | 브라우저에서 접근할 URL 경로 (`/web` → `localhost/web/...`) |
| `reloadable` | 파일 변경 시 자동 재로드 여부 |
| `workDir` | Tomcat 작업 디렉터리 |

> **nano 편집기 저장 단축키**  
> `Ctrl + O` → 저장 / `Enter` → 파일명 확인 / `Ctrl + X` → 종료

---

#### 3) Tomcat 서버 실행 및 브라우저 확인

```bash
# Tomcat 디렉터리로 이동
cd /opt/tomcat             # 설치 경로에 따라 다를 수 있음

# 서버 시작
sudo ./bin/startup.sh

# 서버 종료 (필요 시)
sudo ./bin/shutdown.sh
```

브라우저에서 아래 주소로 접근해 정상 동작 확인:

```
http://localhost/web/emp/list.do
```

3. Ubuntu에 Git 설치 후 사용자 등록 → 저장소 클론 → `classes` 경로 이동 → `server.xml` Context 설정 → Tomcat 실행 → 브라우저 실행 확인까지 전 과정 실습

### 에러 및 해결

**에러 1 — 이클립스 : 이미지 목록이 1개만 출력됨 (taglib 누락)**

| 항목 | 내용 |
|---|---|
| 증상 | `list.do` 실행 시 12개 이미지가 나와야 하는데 누락된 이미지 1개만 출력됨 |
| 원인 파악 과정 | SQL문 및 `Config.xml` DB 연결 확인 → 이상 없음 → 데이터는 오는데 화면에 못 뿌리는 View 문제로 판단 → `list.jsp` 코드 확인 → `<c:forEach>` 태그의 색상이 변하지 않아 태그가 적용되지 않음을 인지 → `taglib` 선언 확인 |
| 원인 | `list.jsp` 상단에 JSTL taglib 선언이 누락되어 있어 `<c:forEach>` 반복문이 동작하지 않았음 |
| 해결 | 파일 상단에 taglib 선언 추가 후 정상 동작 확인 |

```jsp
<%@ taglib prefix="c" uri="http://java.sun.com/jsp/jstl/core" %>
```

> **핵심 교훈**  
> `<c:forEach>` 등 JSTL 태그가 동작하지 않을 때는 taglib 선언 누락을 먼저 의심한다.  
> IDE에서 태그 색상이 변하지 않는다면 선언이 적용되지 않은 신호다.

---

**에러 2 — Ubuntu : `.do` 요청이 동작하지 않음 (classes 경로 문제)**

| 항목 | 내용 |
|---|---|
| 증상 | Ubuntu Tomcat에서 `.jsp`는 실행되나 `.do` 요청 시 에러 발생 |
| 원인 파악 과정 | `.jsp`(화면)는 되고 `.do`(서블릿)만 안 된다는 점에서 컴파일된 클래스 파일 문제로 판단 → 파일 위치 확인 |
| 원인 | `classes` 폴더가 `build/classes`에만 있고 Tomcat이 참조하는 `WEB-INF/classes`에는 없었음 |
| 해결 | `sudo cp -r classes ~/JSPMVCEmpProject/src/main/webapp/WEB-INF` 명령으로 복사 → Tomcat 재시작 → `list.do` 정상 실행 확인 |

> **핵심 교훈**  
> GitHub 클론 프로젝트를 Ubuntu Tomcat에서 실행할 때는 `WEB-INF/classes` 존재 여부를 반드시 확인한다.  
> Eclipse는 `build/classes`를 자동 참조하지만 Tomcat 단독 실행 환경에서는 `WEB-INF/classes`가 기준이다.

---

### 배운점

- Eclipse에서 Share Project로 올리는 방식과 터미널로 직접 푸시하는 방식은 혼용하면 충돌이 발생하므로 프로젝트마다 방식을 일관되게 유지해야 한다는 것을 알게 됨
- Ubuntu 환경에서의 배포는 Eclipse가 자동으로 처리해주던 부분들(classes 경로, Context 설정 등)을 직접 처리해야 하므로 프로젝트의 디렉터리 구조와 Tomcat의 동작 원리를 이해하는 것이 중요함을 체감함
- 에러가 발생했을 때 증상을 좁혀가며 원인을 찾는 과정(DB → 데이터 → View → 태그 → 선언)을 반복 경험하면서 디버깅 사고 방식이 조금씩 잡혀가고 있음
