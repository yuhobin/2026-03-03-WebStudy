## What I Learned

### 1. 동적 쿼리란?

1) 정의

MyBatis에서 **동적 쿼리(Dynamic SQL)**란 실행 시점에 조건에 따라 SQL 문장이 달라지는 쿼리를 말한다.
사용자의 입력값에 따라 WHERE 조건, SET 절, IN 절 등이 유동적으로 구성된다.

2) 사용하는 이유

- 검색 조건이 선택적으로 들어오는 경우 (필터 검색)
- 수정할 컬럼이 상황마다 다른 경우
- IN 절에 가변적인 목록을 전달해야 하는 경우
- 조건 없는 전체 조회와 조건부 조회를 하나의 쿼리로 처리하고 싶은 경우

3) 주요 태그 목록

| 태그 | 역할 |
|------|------|
| `<if>` | 단일 조건 분기 |
| `<choose>` / `<when>` / `<otherwise>` | 다중 조건 분기 (Java의 switch-case) |
| `<where>` | WHERE절 자동 생성 및 AND/OR 정리 |
| `<set>` | UPDATE SET절 자동 생성 및 쉼표 정리 |
| `<trim>` | 앞뒤 특정 문자열 추가/제거 (where, set의 기반 태그) |
| `<foreach>` | 컬렉션 반복 처리 (IN절 등) |
| `<sql>` / `<include>` | SQL 조각 재사용 |
| `<bind>` | 표현식을 변수로 바인딩 |

### 2. if - 단일 조건문

1) 개념

조건이 참일 때만 해당 SQL 조각을 포함시킨다. Java의 `if`문과 동일한 역할이다.

2) 문법

```xml
<if test="조건식">
    SQL 조각
</if>
```

3) 예시

```xml
<select id="searchEmp" resultType="EmpVO">
    SELECT * FROM EMP
    WHERE 1=1
    <if test="ename != null and ename != ''">
        AND ENAME LIKE '%' || #{ename} || '%'
    </if>
    <if test="job != null and job != ''">
        AND JOB = #{job}
    </if>
</select>
```

> `WHERE 1=1`을 고정으로 두면 `<if>` 조건이 하나도 없어도 SQL 문법 오류가 발생하지 않는다.
> 단, 이 방식보다 `<where>` 태그 사용이 더 권장된다.

4) 주의사항

- `test` 속성 안에서 문자열 비교는 `==` 대신 `equals()`를 쓰거나 `!=` 방식으로 처리
- null 체크를 먼저 하고 빈 문자열 체크를 나중에 해야 NPE를 방지할 수 있다

### 3. choose / when / otherwise - 다중 조건문

1) 개념

여러 조건 중 **하나만** 선택하여 실행한다. Java의 `switch-case`와 동일한 구조이며, `<if>`를 여러 개 쓰면 중복 조건이 적용될 수 있는 것과 달리 `<choose>`는 먼저 만족하는 조건 하나만 실행된다.

2) 문법

```xml
<choose>
    <when test="조건1">SQL 조각1</when>
    <when test="조건2">SQL 조각2</when>
    <otherwise>기본 SQL 조각</otherwise>
</choose>
```

3) 예시

```xml
<select id="findEmp" resultType="EmpVO">
    SELECT * FROM EMP
    WHERE
    <choose>
        <when test="empno != null">
            EMPNO = #{empno}
        </when>
        <when test="ename != null">
            ENAME = #{ename}
        </when>
        <otherwise>
            DEPTNO = 10
        </otherwise>
    </choose>
</select>
```

### 4. where - WHERE절 자동 관리

1) 개념

`<where>` 태그는 내부에 조건이 하나라도 존재하면 자동으로 `WHERE` 키워드를 붙여준다. 또한 맨 앞에 오는 `AND` 또는 `OR`를 자동으로 제거한다.

2) `WHERE 1=1` 방식과의 비교

| 방식 | 특징 |
|------|------|
| `WHERE 1=1 + <if>` | 직관적이지만 불필요한 조건이 항상 포함됨 |
| `<where> + <if>` | 조건이 없으면 WHERE 자체가 생략됨, 더 권장되는 방식 |

3) 예시

```xml
<select id="searchEmp" resultType="EmpVO">
    SELECT * FROM EMP
    <where>
        <if test="ename != null and ename != ''">
            AND ENAME LIKE '%' || #{ename} || '%'
        </if>
        <if test="deptno != null">
            AND DEPTNO = #{deptno}
        </if>
    </where>
</select>
```

> 조건이 하나도 없으면 `WHERE`절 자체가 생성되지 않아 전체 조회가 된다.

### 5. set - UPDATE절 자동 관리

1) 개념

UPDATE 문에서 수정할 컬럼이 동적으로 결정될 때 사용한다. `<where>`와 마찬가지로 자동으로 `SET` 키워드를 붙이고, 마지막 불필요한 쉼표(`,`)를 제거한다.

2) 예시

```xml
<update id="updateEmp">
    UPDATE EMP
    <set>
        <if test="ename != null">ENAME = #{ename},</if>
        <if test="job != null">JOB = #{job},</if>
        <if test="sal != null">SAL = #{sal},</if>
    </set>
    WHERE EMPNO = #{empno}
</update>
```

> 각 조건 뒤에 `,`를 붙여두면 `<set>`이 마지막 쉼표를 자동으로 제거한다.

### 6. trim - 접두·접미 문자 제거 및 추가

1) 개념

`<where>`와 `<set>`의 기반이 되는 태그로, 더 세밀하게 앞뒤 문자열을 추가하거나 제거할 수 있다.

2) 속성

| 속성 | 역할 |
|------|------|
| `prefix` | 내용이 존재할 때 앞에 추가할 문자열 |
| `prefixOverrides` | 앞에서 제거할 문자열 (파이프`\|`로 여러 개 지정 가능) |
| `suffix` | 내용이 존재할 때 뒤에 추가할 문자열 |
| `suffixOverrides` | 뒤에서 제거할 문자열 |

3) 예시 - `<where>` 직접 구현

```xml
<!-- 아래 trim은 <where>와 동일하게 동작한다 -->
<trim prefix="WHERE" prefixOverrides="AND | OR">
    <if test="ename != null">AND ENAME = #{ename}</if>
    <if test="job != null">AND JOB = #{job}</if>
</trim>
```

4) 예시 - `<set>` 직접 구현

```xml
<!-- 아래 trim은 <set>과 동일하게 동작한다 -->
<trim prefix="SET" suffixOverrides=",">
    <if test="ename != null">ENAME = #{ename},</if>
    <if test="job != null">JOB = #{job},</if>
</trim>
```

> 실무에서는 보통 `<where>`, `<set>`으로 충분하지만, 복잡한 커스텀 SQL 구성이 필요할 때 `<trim>`을 직접 사용한다.

### 7. foreach - 반복문

1) 개념

List, Array, Map 등 컬렉션을 순회하면서 SQL 조각을 반복 생성한다. 주로 `IN (값1, 값2, ...)` 절을 동적으로 만들 때 사용한다.

2) 속성

| 속성 | 역할 |
|------|------|
| `collection` | 순회할 컬렉션 이름 (List면 `list`, 배열이면 `array`) |
| `item` | 각 요소를 참조하는 변수명 |
| `index` | 현재 인덱스 변수명 (선택) |
| `open` | 시작 문자열 |
| `close` | 종료 문자열 |
| `separator` | 각 요소 사이의 구분자 |

3) 예시 - IN절 처리

```xml
<select id="findByDeptList" resultType="EmpVO">
    SELECT * FROM EMP
    WHERE DEPTNO IN
    <foreach collection="list" item="deptno" open="(" close=")" separator=",">
        #{deptno}
    </foreach>
</select>
```

4) 예시 - 다중 INSERT (Oracle 방식)

```xml
<insert id="insertMultiEmp">
    INSERT ALL
    <foreach collection="list" item="emp">
        INTO EMP (EMPNO, ENAME, JOB) VALUES (#{emp.empno}, #{emp.ename}, #{emp.job})
    </foreach>
    SELECT * FROM DUAL
</insert>
```

5) 예시 - 다중 DELETE (Foreign Key 연쇄 처리)

외래키(FK) 제약이 있는 테이블에서 여러 행을 삭제할 때, 자식 테이블을 먼저 삭제한 후 부모 테이블을 삭제해야 한다. `<foreach>`를 활용하면 SQL 문장 여러 개를 동시에 처리할 수 있다.

```xml
<!-- 자식 먼저 삭제 -->
<delete id="deleteChildren">
    DELETE FROM REPLY
    WHERE BOARD_NO IN
    <foreach collection="list" item="no" open="(" close=")" separator=",">
        #{no}
    </foreach>
</delete>

<!-- 부모 삭제 -->
<delete id="deleteBoards">
    DELETE FROM BOARD
    WHERE BOARD_NO IN
    <foreach collection="list" item="no" open="(" close=")" separator=",">
        #{no}
    </foreach>
</delete>
```

### 8. sql / include - 중복 제거

1) 개념

여러 쿼리에서 반복되는 SQL 조각을 `<sql>`로 정의하고 `<include>`로 불러와 재사용한다. 컬럼 목록, 공통 WHERE 조건 등에 활용된다.

2) 예시

```xml
<!-- SQL 조각 정의 -->
<sql id="empColumns">
    EMPNO, ENAME, JOB, MGR, HIREDATE, SAL, COMM, DEPTNO
</sql>

<!-- include로 재사용 -->
<select id="selectAll" resultType="EmpVO">
    SELECT <include refid="empColumns"/>
    FROM EMP
</select>

<select id="selectByDept" resultType="EmpVO">
    SELECT <include refid="empColumns"/>
    FROM EMP
    WHERE DEPTNO = #{deptno}
</select>
```

### 9. bind - 변수 바인딩

1) 개념

OGNL 표현식을 사용하여 복잡한 값(문자열 가공, 대소문자 변환 등)을 변수로 만들어 SQL에서 재사용할 수 있게 한다. 특히 LIKE 검색에서 `%` 연결 처리나 대소문자 무시 검색에 유용하다.

2) 문법

```xml
<bind name="변수명" value="OGNL 표현식"/>
```

3) 예시 - 대소문자 구분 없이 LIKE 검색

```xml
<select id="searchByName" resultType="EmpVO">
    <bind name="uname" value="ename.toUpperCase()"/>
    SELECT * FROM EMP
    WHERE UPPER(ENAME) LIKE '%' || #{uname} || '%'
</select>
```

4) 예시 - LIKE 패턴을 변수로 미리 구성

```xml
<select id="searchEmp" resultType="EmpVO">
    <bind name="pattern" value="'%' + keyword + '%'"/>
    SELECT * FROM EMP
    WHERE ENAME LIKE #{pattern}
</select>
```

> `bind`를 활용하면 SQL 내에서 문자열 연산을 DB 종류(Oracle, MySQL 등)에 상관없이 Java 표현식으로 통일할 수 있다.

### 10. 동적 쿼리 활용 패턴

1) PROCEDURE와의 병행 활용

복잡한 비즈니스 로직(댓글 수 증감, 좋아요, 찜하기 등 공통 기반 처리)은 DB의 **STORED PROCEDURE**로 처리하고, MyBatis 동적 쿼리는 조회·단순 CUD에 집중하는 방식으로 역할을 분리하는 것이 일반적이다.

| 처리 방식 | 적합한 경우 |
|-----------|-------------|
| 동적 쿼리 | 검색 조건 필터, 선택적 업데이트 |
| PROCEDURE | 공통 로직 (댓글, 좋아요, 찜하기), 트랜잭션 묶음 처리 |

2) 필터 검색 구현 흐름

```
사용자 입력 (검색 조건 선택)
    ↓
Controller → VO/Map에 조건 담아 Service 전달
    ↓
Mapper XML에서 <where> + <if> 조합으로 동적 쿼리 생성
    ↓
조건에 맞는 SQL 실행 → 결과 반환
```

3) 태그 선택 가이드

```
조건이 있을 수도 없을 수도 있는 WHERE절  → <where> + <if>
여러 조건 중 하나만 선택                  → <choose> / <when> / <otherwise>
수정 컬럼이 동적인 UPDATE                 → <set> + <if>
IN절에 가변 목록 전달                     → <foreach>
반복되는 컬럼 목록 등 공통 SQL 조각       → <sql> + <include>
문자열 가공 / 대소문자 처리               → <bind>
세밀한 앞뒤 문자 제거·추가               → <trim>
```

### 배운 점

- `WHERE 1=1` 방식은 직관적이지만 `<where>` 태그를 쓰는 것이 더 깔끔하고 조건이 없을 때 불필요한 WHERE절이 생기지 않는다는 것을 알게 되었다.
- `<trim>`이 `<where>`와 `<set>`의 기반 태그라는 것을 알고 나니 세 태그의 관계가 명확하게 이해되었다.
- `<foreach>`로 IN절을 처리하는 것이 Java에서 반복문으로 SQL을 문자열로 조합하는 것보다 훨씬 안전하고 간결하다는 것을 체감했다.
- `<bind>`를 이용하면 DB 종류에 상관없이 Java 표현식으로 문자열 처리를 통일할 수 있어 이식성이 높아진다.
