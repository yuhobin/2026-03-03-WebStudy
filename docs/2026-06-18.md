## What I Learned

### 1. 저장공간 개요

1) 웹에서의 상태 관리

HTTP는 기본적으로 **stateless(무상태)** 프로토콜이기 때문에 요청이 끝나면 서버는 이전 요청을 기억하지 못한다. 이를 보완하기 위해 **Session**과 **Cookie**를 사용하여 상태를 유지한다.

2) 종류 요약

| 저장공간 | 저장 위치 | 저장 단위 | 주요 용도 |
|----------|-----------|-----------|-----------|
| Session | 서버 | Object | 로그인 정보 유지 |
| Cookie | 브라우저 | 문자열(String) | 자동 로그인, 최근 방문, 장바구니 |

3) 생성 방법

```java
// Session 생성
HttpSession session = request.getSession();

// Cookie 조회
Cookie[] cookies = request.getCookies();
```

### 2. Session

1) 개념

서버에 저장되는 저장공간으로, 브라우저 접속 시 사용자 1명당 1개씩 생성된다. 브라우저 종료 또는 로그아웃 시 삭제된다.

2) 특징

- 저장 단위 : `Object` (어떤 타입이든 저장 가능)
- 내장 객체 : `HttpSession`
- `request.getSession()`으로 생성
- 브라우저 종료 / 로그아웃 시 삭제

3) Port가 다른 경우 (CORS 관련)

React + Spring Boot처럼 클라이언트와 서버의 포트가 다를 경우 Session을 공유할 수 없다.

```
React (client) : port 3000
Spring Boot (server) : port 8080
```

이 경우 JavaScript의 Session 대신 **JWT(JSON Web Token)** 방식을 사용한다.
JWT는 Cookie 기반으로 동작하며, 카카오 로그인 등 OAuth 인증에도 활용된다.

4) 주요 메소드

| 메소드 | 설명 |
|--------|------|
| `setAttribute(String key, Object value)` | 데이터 저장 |
| `getAttribute(String key)` | 데이터 조회 → JSP에서 `${sessionScope.key}` |
| `invalidate()` | 세션 전체 해제 (로그아웃, 브라우저 종료 시) |
| `isNew()` | 처음 생성된 세션인지 확인 → 장바구니 처리에 활용 |
| `getId()` | 세션 고유 ID 반환 → 사용자 구분, 채팅 구현 등에 활용 |
| `setMaxInactiveInterval(int seconds)` | 세션 유지 시간 설정 (기본값 : 1800초 = 30분) |

5) 주요 활용

- 로그인 시 사용자 정보 저장
- 장바구니 (`isNew()`로 최초 생성 여부 확인)
- 채팅 (`getId()`로 사용자 식별)

### 3. Cookie

1) 개념

브라우저에 저장되는 저장공간이다. `new Cookie()`로 생성하며 **문자열(String)만** 저장할 수 있다.

2) 특징

- 저장 단위 : `String`
- 브라우저에 저장되므로 서버 재시작 후에도 유지
- 유효 시간 설정 가능

3) 주요 메소드

| 메소드 | 설명 |
|--------|------|
| `new Cookie(String key, String value)` | 쿠키 생성 및 저장 |
| `setPath("/")` | 쿠키 유효 경로 설정 (전체 경로) |
| `getName()` | 쿠키 key 읽기 |
| `getValue()` | 쿠키 value 읽기 |
| `setMaxAge(0)` | 쿠키 삭제 (0 설정 시 즉시 만료) |

> `setMaxAge()` 단위는 **초(second)** 기준이다.

4) 주요 활용

- 자동 로그인
- 최근 방문 페이지 기록
- 장바구니 (비로그인 상태)

### 4. Session vs Cookie 비교

1) 핵심 차이

| 항목 | Session | Cookie |
|------|---------|--------|
| 저장 위치 | 서버 | 브라우저 |
| 저장 타입 | Object | String |
| 보안 | 상대적으로 안전 | 상대적으로 취약 |
| 유지 기간 | 브라우저 종료 시 삭제 | `setMaxAge()`로 직접 설정 |
| 용량 제한 | 서버 메모리 의존 | 약 4KB |

2) 상태 관리 프로그램으로서의 역할

Cookie와 Session은 모두 **상태 관리 프로그램**으로, Vue / React 같은 SPA 프레임워크에서 데이터 유지를 위해 함께 활용된다.

### 5. 내장 객체 - request / response / application

1) request

클라이언트의 요청 정보를 담고 있는 객체다.

| 메소드 | 설명 |
|--------|------|
| `getParameter(String name)` | 요청 파라미터 1개 조회 → `String` 반환 |
| `getParameterValues(String name)` | 요청 파라미터 여러 개 조회 → `String[]` 반환 |
| `setAttribute(String key, Object value)` | request 범위에 데이터 저장 |
| `getAttribute(String key)` | request 범위 데이터 조회 → JSP에서 `${key}` |
| `getSession()` | Session 객체 생성/반환 |
| `getCookies()` | Cookie 배열 반환 |

2) response

서버에서 클라이언트로의 응답을 처리하는 객체다.

| 메소드 | 설명 |
|--------|------|
| `setContentType("text/html")` | 응답 타입 설정 (`text/xml`, `text/plain` JSON 등) |
| `addCookie(Cookie cookie)` | 쿠키 전송 |
| `setHeader(String name, String value)` | 응답 헤더 설정 |
| `sendRedirect(String url)` | 다른 URL로 리다이렉트 |

3) application

서버 전체에서 공유되는 객체다.

| 메소드 | 설명 |
|--------|------|
| `getRealPath(String path)` | 실제 파일 시스템 경로 반환 |
| `getResource(String path)` | 운영체제와 관계없이 리소스 접근 가능 |

### 6. MVC 흐름

1) 전체 처리 흐름

```
브라우저 (.do 요청)
    ↓ request
DispatcherServlet (Controller)
    ↓ request
Model ↔ DAO (DB 처리)
    ↓ request 안에 출력에 필요한 데이터를 담아서 전달
DispatcherServlet
    ↓ request
JSP (View - 결과 출력)
```

2) 흐름 설명

- 브라우저에서 `.do` 형식으로 요청이 들어온다
- `DispatcherServlet`(Controller)이 요청을 받아 적절한 Model을 호출한다
- Model은 DAO를 통해 DB와 통신하고 결과 데이터를 `request`에 담는다
- `DispatcherServlet`이 해당 JSP로 `forward`하여 View가 데이터를 출력한다

### 7. MyBatis

1) 개요

MyBatis는 Java와 SQL을 분리하여 관리할 수 있게 해주는 **SQL Mapper 프레임워크**다. JDBC의 반복 코드(Connection, PreparedStatement, ResultSet 등)를 자동으로 처리한다.

2) 환경 설정 파일 구조

| 파일 | 역할 | 생성 수 |
|------|------|---------|
| `Config.xml` | 환경 설정 (DB Connection 관련) | 1개만 생성 |
| `mapper.xml` | SQL 저장 파일 | 테이블마다 생성 |

3) DAO에서 사용하는 주요 메소드

| 메소드 | 반환 타입 | 설명 |
|--------|-----------|------|
| `selectList("id명", 매개변수)` | `List` | 여러 행 조회 |
| `selectOne("id명", 매개변수)` | VO / Object | 단일 행 조회 |
| `insert("id명", 매개변수)` | `int` | 삽입 |
| `update("id명", 매개변수)` | `int` | 수정 |
| `delete("id명", 매개변수)` | `int` | 삭제 |

4) 파라미터 전달 방식

```
파라미터가 1개  → 기본 타입 또는 String 직접 전달
파라미터가 여러 개 → HashMap 또는 VO로 묶어서 전달

HashMap 사용 시 : #{id} → map.get("id")
VO 사용 시      : #{id} → vo.getId()
```

5) mapper.xml 주요 속성

| 속성 | 설명 |
|------|------|
| `id` | 쿼리 구분자 (모든 mapper 통틀어 중복 불가) |
| `resultType` | SQL 실행 결과를 담을 타입 (VO, int, String 등) |
| `parameterType` | `#{}` 에 채울 파라미터 타입 |
| `resultMap` | JOIN 결과 또는 컬럼명과 필드명이 다를 때 사용 |
| `parameterMap` | PROCEDURE 사용 시 IN / OUT / INOUT 변수 설정 |

6) PROCEDURE 연동

반복이 많거나, 보안이 필요하거나, 트랜잭션 묶음 처리가 필요한 경우 STORED PROCEDURE를 활용한다. MyBatis에서는 `parameterMap`을 통해 IN / OUT / INOUT 파라미터를 설정하여 연동한다.

```sql
CREATE PROCEDURE pro_name(pName VARCHAR2(10), ...)
```

활용 예시 : 전체 댓글 처리, 좋아요, 찜하기 등 공통 기반 로직

7) Session(접속) 관리

```java
// SELECT : autoCommit false (기본값)
SqlSession session = ssf.openSession();

// DML (INSERT / UPDATE / DELETE) : autoCommit true
SqlSession session = ssf.openSession(true);

// 사용 후 반드시 반환 (커넥션 재사용)
session.close();
```

### 8. jQuery

1) 개요

jQuery는 JavaScript를 간결하게 작성할 수 있게 해주는 라이브러리다. DOM 조작, 이벤트 처리, 서버 통신(Ajax) 기능을 제공한다.

2) 기본 선택자

```javascript
$('태그명')   // 태그 선택
$('#id명')    // ID 선택
$('.class명') // 클래스 선택
$('선택자')   // CSS 선택자 그대로 사용 가능
```

3) 값 읽기 / 조작 메소드

| 메소드 | 설명 |
|--------|------|
| `val()` | `input`, `select`, `textarea` 값 읽기/쓰기 |
| `text()` | 태그 내부 텍스트 읽기/쓰기 |
| `html()` | 태그 내부 HTML 읽기/쓰기 |
| `attr()` | 태그 속성값 읽기/쓰기 |
| `append()` | 태그 내부 끝에 내용 추가 |

4) 이벤트 처리

```javascript
$('선택자').on('이벤트명', function() {
    // 처리 내용
});
```

| 이벤트 | 설명 |
|--------|------|
| `click` | 클릭 시 |
| `change` | 값 변경 시 |
| `keyup` | 키보드 키를 뗄 때 |
| `mousedown` | 마우스 버튼 누를 때 |
| `hover` | 마우스 올릴 때 |

5) 효과

| 메소드 | 설명 |
|--------|------|
| `show()` | 요소 보이기 |
| `hide()` | 요소 숨기기 |
| `fadeIn()` | 서서히 나타나기 |
| `fadeOut()` | 서서히 사라지기 |

6) 서버 통신 (Ajax)

```javascript
$.ajax({
    type: 'GET' or 'POST',          // 요청 방식
    url: '연결할 서버 주소',
    data: { "키": "값" },           // JSP로 전송할 데이터
    success: function(result) {     // 정상 수행 시 결과값 처리
        // result 출력
    },
    error: function(error) {        // 에러 발생 시 처리
        console.log(error);
    }
});
```

7) Ajax 통신 방식 비교

| 방식 | 설명 |
|------|------|
| `$.ajax()` | jQuery 기반, 옵션이 많고 직관적 |
| `fetch()` | JavaScript 내장 함수 |
| `axios()` | 가장 많이 사용됨, Vue / React와 주로 사용 |

### 배운 점

- Session과 Cookie의 저장 위치가 다르기 때문에 보안과 유지 기간 측면에서 쓰임새가 다르다는 것을 정리할 수 있었다.
- React + Spring Boot처럼 포트가 다른 구조에서는 Session을 쓸 수 없고 JWT를 활용해야 한다는 것을 처음 명확하게 인식했다.
- MyBatis에서 파라미터가 여러 개일 때 HashMap과 VO 중 어느 것을 써야 하는지 기준이 정리되었다.
- Ajax 통신 방식이 `$.ajax()` → `fetch()` → `axios()` 순으로 발전해왔고, 현재 실무에서는 `axios()`가 주류라는 흐름을 이해했다.
