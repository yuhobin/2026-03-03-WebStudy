## 1. Vue 인스턴스 전체 구조

```javascript
Vue.createApp({
    data()     { return { /* HTML에 바인딩되는 변수, this.변수명으로 접근 */ } },
    created()  { /* Vue 객체 생성 직후 */ },
    mounted()  { /* DOM 로드 완료 후 */ },
    updated()  { /* data 변경 → DOM 갱신 후 */ },
    unmounted(){ /* Vue 객체 해제 시 */ },
    methods:   { /* 이벤트 처리 / 공통 함수 */ },
    computed:  { /* 계산된 속성 */ },
    watch:     { /* 데이터 변경 감시 */ },
    components:{ /* 자식 컴포넌트 등록 */ }
}).mount("#app");
```

## 2. 생명주기 함수 (Lifecycle Hooks)

| 훅 함수 | 실행 시점 | 주요 용도 |
|---------|----------|---------|
| `created()` | Vue 객체 생성 직후 | WebSocket 연결, 초기 설정 |
| `mounted()` | DOM 연결 완료 | Axios 초기 호출 *(= jQuery `$(function(){})`)* |
| `updated()` | 데이터 변경 → DOM 갱신 후 | 변경 후 후처리 |
| `unmounted()` | Vue 객체 해제 | 타이머·연결 해제, 메모리 정리 |

## 3. 서버 통신 - Axios

화면 전환 없이 그 자리에서 데이터만 처리 (`ajax` ⊂ `axios` ⊂ `fetch`)

```javascript
// GET
axios.get('/api/list')
    .then(response => {
        this.list = response.data; // response.data : 실제 전송된 데이터
    });

// POST (데이터 없을 경우 null, {} 전달)
axios.post('/api/save', null, {});
```

> jQuery는 응답 데이터로 **HTML 태그를 직접 생성**해서 추가하지만,  
> Vue는 **데이터만 변경하면 HTML이 자동 갱신**됨 → 코드 훨씬 단순

## 4. Arrow Function과 this 바인딩

Axios `.then()` 콜백 안에서 `this`가 가리키는 대상에 주의

```javascript
// X 일반 function : this가 Vue 인스턴스가 아닌 function 자체를 가리킴
axios.get(url).then(function(response) {
    this.list = response.data; // 오류
});

// 해결법 1 : _this에 미리 저장
let _this = this;
axios.get(url).then(function(response) { _this.list = response.data; });

//  해결법 2 (권장) : Arrow Function은 외부 스코프의 this 사용
axios.get(url).then(response => { this.list = response.data; });
```

## 5. computed - 계산된 속성

`data()`의 값을 **가공·계산해서 반환**하는 속성.  
참조하는 데이터가 변경되면 자동으로 재계산됨.

```javascript
data() {
    return {
        price: 15000,
        qty: 3
    }
},
computed: {
    // 총금액 = 단가 × 수량 (자동 재계산)
    totalPrice() {
        return (this.price * this.qty).toLocaleString() + '원'; // 45,000원
    }
}
```

```html
<input type="number" v-model.number="qty">
<p>총 금액 : {{ totalPrice }}</p>
```

| 구분 | methods | computed |
|------|---------|----------|
| 호출 방식 | `함수()` 로 호출 | 변수처럼 `{{ totalPrice }}` 참조 |
| 재실행 조건 | 호출될 때마다 실행 | 참조 데이터가 변경될 때만 재계산 |
| 주요 용도 | 이벤트 처리 | 데이터 가공, 천단위 콤마, 합계 등 |

## 6. 디렉티브 (Directive)

| 디렉티브 | 축약 | 역할 |
|---------|------|------|
| `v-for` | - | 배열/숫자 반복 렌더링 |
| `v-if` / `v-else` | - | 조건부 렌더링 (DOM 제거) |
| `v-show` | - | 조건부 표시 (`display` 제어, DOM 유지) |
| `v-model` | - | 입력값 양방향 바인딩 |
| `v-on:이벤트` | `@` | 이벤트 리스너 등록 |
| `v-bind:속성` | `:` | 속성에 데이터 주입 (단방향) |

```html
<li v-for="item in list" :key="item.id">{{ item.name }}</li>
<p v-if="isLogin">환영합니다</p>
<input v-model="keyword">
<button @click="handleClick">확인</button>
<img :src="imageUrl">
```

>  `v-for`와 `v-if`는 **같은 태그에 동시 사용 불가**  
> → `<template v-if="">` 로 감싸거나 `computed`로 미리 필터링

## 7. 컴포넌트 통신 - Props & Emit

```
Parent ──── props (데이터) ────► Child
Parent ◄─── $emit (이벤트) ──── Child
```

### 1) Props - 부모 → 자식 데이터 전달

```javascript
// 자식 컴포넌트
props: { startPage: Number, totalCount: Number }  // 여러 개
props: ['startPage']                               // 1개
```

```html
<!-- camelCase → kebab-case 변환 필수 : startPage → :start-page -->
<pagecard :start-page="startPage" @page-change="pageChange" />
```

### 2) Emit - 자식 → 부모 이벤트 전달

```javascript
// 자식 : 부모에게 이벤트 + 데이터 전달
emits: ['page-change']
this.$emit('page-change', 5);

// 부모 : 이벤트 수신 후 처리
pageChange(page) {
    this.curPage = page;
    axios.get(`/api/list?page=${page}`).then(r => { this.list = r.data; });
}
```

> **$emit을 쓰는 이유** : 자식은 부모 데이터를 직접 변경할 수 없음  
> 데이터 소유권은 선언한 컴포넌트(부모)에 있으며, **단방향 데이터 흐름 원칙**을 지켜야 유지보수가 용이함

| 구분 | 방향 | 방법 |
|------|------|------|
| `props` | 부모 → 자식 | `:변수명="값"` |
| `$emit` | 자식 → 부모 | `$emit('이벤트명', 값)` |

### 배운 점
- `created()`는 WebSocket처럼 DOM 없이도 되는 초기 연결, `mounted()`는 DOM이 필요한 Axios 호출에 사용한다는 차이를 이해함
- Axios 콜백에서 Arrow Function을 써야 Vue 인스턴스의 `this`를 그대로 사용할 수 있음을 이해함
- `computed`는 `methods`와 달리 참조 데이터가 바뀔 때만 재계산되므로, 총금액처럼 데이터 기반 계산에 더 적합함
- 자식 컴포넌트가 부모 데이터를 직접 수정하지 않고 `$emit`으로 요청하는 이유가 단방향 데이터 흐름 원칙 때문임을 이해함
