## 1. 크롤링 개요

웹 페이지에서 원하는 데이터를 자동으로 수집하는 기술로, 크게 두 가지 방식으로 나뉜다.

- **정적 크롤링** : 서버에서 받은 HTML을 그대로 파싱
- **동적 크롤링** : 브라우저를 실제로 실행해 JavaScript까지 처리된 결과를 파싱

맛집 사이트처럼 JavaScript로 데이터를 동적으로 불러오는 경우, 정적 크롤링으로는 빈 데이터만 수집되므로 사이트 구조에 맞는 방식 선택이 중요하다.

> **선택 기준** : 페이지 소스 보기(`Ctrl+U`)에서 원하는 데이터가 보이면 → Jsoup, 없으면 → Playwright

---

## 2. Jsoup

Java 기반의 정적 크롤링 라이브러리로, URL에 HTTP 요청을 보내 받아온 HTML을 CSS 선택자로 파싱한다.

- 별도 브라우저 없이 가볍고 빠르게 동작
- JavaScript를 실행하지 않으므로 동적으로 로딩되는 데이터는 수집 불가
- 전통적인 서버사이드 렌더링 방식의 사이트에 적합

---

## 3. Playwright

Microsoft에서 개발한 동적 크롤링 라이브러리로, 실제 브라우저(Chromium 등)를 자동으로 조작해 JavaScript 실행 결과까지 수집한다. Java / Python / Node.js를 지원한다.

- 실제 브라우저처럼 동작하므로 SPA, 동적 로딩 사이트 크롤링 가능
- 브라우저를 띄우는 만큼 Jsoup에 비해 느리고 리소스 소비가 큼
- 렌더링 완료 타이밍을 맞추는 대기 처리가 핵심
- Headless 모드로 브라우저 창을 숨기거나 표시해서 디버깅 가능

---

## 4. Jsoup vs Playwright 비교

| 구분 | Jsoup | Playwright |
|------|-------|------------|
| 방식 | 정적 크롤링 | 동적 크롤링 |
| JavaScript 실행 | ❌ | ✅ |
| 속도 | 빠름 | 느림 |
| 리소스 | 가벼움 | 무거움 (브라우저 실행) |
| 적합한 사이트 | 전통적인 HTML 기반 사이트 | SPA, 동적 로딩 사이트 |
| 난이도 | 낮음 | 상대적으로 높음 |

## NOTE

### 오늘 한 일
- Jsoup과 Playwright를 각각 활용해 맛집 사이트 크롤링 실습
- 수집한 데이터를 DB에 적재하는 과정 진행
- 크롤링 중 발생한 NOT NULL 제약 조건 오류 디버깅 및 해결

### 트러블슈팅 - price 컬럼 NOT NULL 오류
크롤링한 데이터를 DB에 저장하는 과정에서 오류가 발생했다.  
`price` 컬럼을 NOT NULL로 설정해 두었는데, 실제 맛집 사이트에서 가격대 정보가 없는 경우 null 값이 들어오면서 제약 조건 위반 오류가 난 것이었다.

`price` 컬럼의 NOT NULL 제약을 제거하고 다시 크롤링을 진행하니, 가격대가 없는 맛집은 null로, 있는 맛집은 정상 값으로 저장되며 데이터가 순차적으로 정상 적재되었다.

### 배운 점
- 실제 사이트 데이터는 설계 시 예상한 것과 다르게 null이 존재할 수 있으므로, 크롤링 전 대상 사이트의 데이터 패턴을 먼저 확인하고 DB 스키마를 설계해야 한다
- Playwright는 브라우저 동작을 눈으로 확인하며 디버깅할 수 있다는 점이 유용했다
- 두 방식을 직접 비교해보며 사이트 구조에 따라 적절한 도구를 선택하는 것이 중요하다는 것을 이해함
