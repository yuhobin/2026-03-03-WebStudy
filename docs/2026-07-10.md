## 1. 가상 DOM (Virtual DOM)

면접 단골 질문으로, Vue / React 모두 가상 DOM을 사용한다.

```
가상 DOM (임시 메모리)  ──── diff 비교 ────► 변경된 부분만 실제 DOM에 반영
                                                     │
                                               브라우저 화면 갱신
```

- 실제 DOM 전체를 다시 그리지 않고 **변경된 부분만 갱신** → 렌더링 성능 최적화
- `mount("CSS선택자")` 로 지정한 영역만 부분적으로 제어
- DOM은 HTML을 **트리 구조**로 표현한 것

## 2. Vue 인스턴스 핵심 옵션

```javascript
Vue.createApp({
    data() {
        return { /* 화면에 바인딩되는 변수. 내부에서 this.변수명으로 접근 */ }
    },
    mounted()  { /* DOM 로드 완료 후. 서버 데이터 초기 로딩 (Axios) */ },
    created()  { /* Vue 객체 생성 직후. WebSocket 연결 등 */ },
    updated()  { /* data 변경 → DOM 갱신 후 */ },
    methods:   { /* 이벤트 처리 함수. 가장 많이 사용 */ },
    computed:  { /* 데이터 가공·계산·필터링. 참조 데이터 변경 시에만 재실행 */ },
    watch:     { /* 특정 데이터 변화 감지 */ },
    components:{ /* 자식 컴포넌트 등록 (목록, 상세보기, 결제 등) */ }
}).mount("#app");
```

> `data`, `methods` 내부에서는 반드시 **`this.변수명`** 으로 접근

## 3. 디렉티브 요약

| 디렉티브 | 설명 | 주요 사용 상황 |
|---------|------|-------------|
| `v-model` | 양방향 바인딩 | input, select, textarea, checkbox, radio |
| `v-bind` (`:`) | 속성 바인딩 (단방향) | `:src`, `:href`, `:disabled` |
| `v-for` | 반복 렌더링 | 목록 출력, `:key` 필수 |
| `v-if` / `v-else` | 조건부 렌더링 (DOM 제거) | 로그인 여부, 조건 분기 |
| `v-show` | 토글 표시 (`display` 제어) | 에러 메시지, 드롭다운 |
| `v-on` (`@`) | 이벤트 리스너 | `@click`, `@keydown.enter` |
| `v-text` / `{{}}` | 텍스트 출력 | 일반 데이터 출력 |
| `v-html` | HTML 파싱 출력 | 뉴스·공지사항 HTML 콘텐츠 |
| `v-once` | 최초 1회만 렌더링 | ID 등 변하지 않는 값 |

**기능별 디렉티브 조합**

| 기능 | 주로 사용하는 디렉티브 |
|------|-------------------|
| 로그인 / 회원가입 검증 | `v-model`, `@submit.prevent`, `v-show`, `:disabled` |
| 목록 출력 | `v-for`, `v-html`, `:src` |
| **검색 (필터링)** | **`v-model`, `computed`, `v-for`, `v-if`** |

## 4. 검색 기능 구현 - computed 필터링

Vue에서 검색은 **서버 요청 없이 클라이언트에서 데이터를 필터링**하는 방식이 핵심이다.
검색어가 바뀔 때마다 `computed`가 자동으로 재실행되어 목록이 즉시 갱신된다.

### 1) 동작 흐름

```
사용자 검색어 입력 (v-model)
        │
        ▼
computed 자동 재실행 (keyword 변경 감지)
        │  전체 list에서 keyword 포함 항목만 필터링
        ▼
v-for로 필터링된 목록 렌더링
        │
        ▼
화면 실시간 갱신 (서버 요청 없음)
```

### 2) 구현 구조

```javascript
Vue.createApp({
    data() {
        return {
            keyword: '',        // v-model로 검색 input과 연결
            list: []            // 서버에서 받아온 전체 데이터
        }
    },
    mounted() {
        // 초기 데이터 로딩
        axios.get('/api/food/list').then(res => { this.list = res.data; });
    },
    computed: {
        // keyword가 바뀔 때마다 자동 재계산
        filteredList() {
            if (!this.keyword) return this.list;
            return this.list.filter(vo =>
                vo.name.includes(this.keyword) ||
                vo.address.includes(this.keyword)
            );
        }
    }
}).mount("#searchApp");
```

```html
<!-- 검색 입력창 -->
<input v-model="keyword" type="text" placeholder="검색어 입력">

<!-- 필터링된 목록 출력 -->
<div v-for="vo in filteredList" :key="vo.no">
    <p>{{ vo.name }}</p>
</div>

<!-- 결과 없음 처리 -->
<p v-if="filteredList.length === 0">검색 결과가 없습니다.</p>
```

### 3) methods vs computed

| 구분 | methods | computed |
|------|---------|---------|
| 재실행 조건 | 호출될 때마다 | 참조 데이터가 변경될 때만 |
| 캐싱 | ❌ | ✅ (동일 keyword면 재계산 안 함) |
| 검색에서의 역할 | 버튼 클릭 이벤트 처리 | 검색어 기반 자동 필터링 |

> 검색처럼 데이터 기반으로 자동 갱신이 필요한 경우 `methods`보다 **`computed`가 적합**하다.

### 배운 점
- 가상 DOM이 변경된 부분만 실제 DOM에 반영하는 구조 덕분에 검색어가 바뀔 때마다 목록 전체를 다시 그리지 않고 효율적으로 갱신됨을 이해함
- 검색에 `computed`를 쓰는 이유는 `keyword`가 바뀔 때만 자동 재실행되고 결과를 캐싱하기 때문으로, `methods`로 매번 호출하는 것보다 성능상 유리함을 이해함
- `v-model`로 검색 input과 data를 양방향 바인딩하면 별도 이벤트 처리 없이도 입력값 변화를 즉시 감지할 수 있다는 점이 jQuery와 가장 다른 부분임을 이해함
