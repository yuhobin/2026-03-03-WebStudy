## 1. 게시판 CRUD

게시판의 모든 기능은 HTTP 메서드와 DB 연산의 1:1 대응으로 구성된다.

| 기능 | HTTP | DB | 화면 이동 |
|------|------|----|---------|
| 목록 조회 | GET | SELECT | 목록 페이지 |
| 글 작성 | POST | INSERT | 작성 완료 → 목록으로 redirect |
| 상세 조회 | GET | SELECT | 상세 페이지 |
| 글 수정 | POST | UPDATE | 수정 완료 → 상세로 redirect |
| 글 삭제 | POST / DELETE | DELETE | 삭제 완료 → 목록으로 redirect |

> INSERT / UPDATE / DELETE 후에는 반드시 **redirect** 처리  
> → 새로고침 시 동일한 요청이 재실행되는 중복 제출 문제 방지 (PRG 패턴)

## 2. 게시판 처리 흐름

### 1) 글 작성

```
글 작성 폼 (GET)
    │  제목 / 내용 / 작성자 입력
    ▼
POST 요청 → Controller → Service → DAO
    │                               │
    │                         board 테이블 INSERT
    ▼
redirect → 목록 페이지
```

### 2) 수정 / 삭제

```
상세 페이지
    ├── [수정] → 수정 폼 → POST → UPDATE → redirect 상세 페이지
    └── [삭제] → POST → DELETE → redirect 목록 페이지
```

- 수정·삭제는 **본인 작성 글만 가능**하도록 세션의 로그인 정보와 게시글 작성자를 비교
- 권한이 없는 경우 수정·삭제 버튼 자체를 렌더링하지 않거나 서버에서 재검증

## 3. 게시판 데이터 설계

**board 테이블 주요 컬럼**

| 컬럼 | 설명 |
|------|------|
| `no` | 게시글 번호 (PK, AUTO_INCREMENT) |
| `id` | 작성자 ID (FK) |
| `title` | 제목 |
| `content` | 내용 |
| `regdate` | 작성일 |
| `hit` | 조회수 |

- 상세 페이지 진입 시 `view_count UPDATE` 처리 (본인 글 제외 옵션)
- 삭제는 실제 DELETE 대신 `status` 컬럼으로 **소프트 삭제** 처리하는 것이 일반적

## 4. 찜하기 (토글 좋아요)

버튼 한 번으로 좋아요 추가 / 취소가 전환되는 토글 방식으로 구현한다.  
화면 전환 없이 버튼 상태만 바뀌어야 하므로 **Ajax 비동기** 처리가 핵심이다.

### 1) DB 구조

```
like 테이블
  ├── id  (FK)   ← 누가
  └── no  (FK)   ← 어떤 맛집을
```

- `id + no` 조합이 **PK** → 한 사용자가 같은 대상에 중복 좋아요 방지

### 2) 토글 처리 흐름

```
찜하기 버튼 클릭 (Ajax)
        │
        ▼
DB 조회 : 해당 id + no 존재 여부 확인
        │
        ├── 없음 → INSERT → 버튼 상태 : 찜 활성화 (♥)
        └── 있음 → DELETE → 버튼 상태 : 찜 해제 (♡)
```

### 3) Controller 처리

```java
// 찜 상태에 따라 INSERT / DELETE 분기
@PostMapping("/like/toggle")
@ResponseBody
public String toggle(@RequestParam int no, HttpSession session) {
    String id = (String) session.getAttribute("id");
    // 존재하면 DELETE, 없으면 INSERT → 결과 반환
}
```

- 반환값(insert / delete)을 받아 프론트에서 버튼 아이콘·텍스트 변경
- 로그인하지 않은 사용자가 클릭하면 로그인 페이지로 유도

- 찜하기는 DB에 row가 있으면 DELETE, 없으면 INSERT하는 단순한 토글 구조지만, `id + no` 복합 PK로 중복을 DB 레벨에서 원천 차단하는 설계가 중요함을 이해함
