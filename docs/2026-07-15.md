## 1. 예약 시스템 구조

예약 기능은 **화면 전환 없이 데이터만 갱신**되는 방식으로 구현한다.  
사용자가 날짜·시간·인원을 선택할 때마다 예약 정보가 즉시 반영되어야 하므로 Ajax 비동기 통신이 핵심이다.

**전체 흐름**
```
사용자 입력 (날짜 / 시간 / 인원 선택)
        │
        │  Ajax 비동기 요청
        ▼
@RestController (예약 가능 여부 확인 / 예약 저장)
        │
        ▼
Service → Repository → DB
        │
        ▼
응답 데이터 → 예약 정보 영역 실시간 갱신
```

---

## 2. 화면 구성

3단 레이아웃으로 구성되며, 각 영역이 독립적으로 데이터를 갱신한다.

```
┌──────────┬──────────────┬──────────────┐
                                      
   맛집        예약 달력      예약 정보  
   리스트     (날짜 선택)    (실시간 갱신)
                                      
└──────────┴──────────────┴──────────────┘
         [예약 시간 버튼] [예약 인원 버튼]
```

| 영역 | 역할 |
|------|------|
| 좌측 - 맛집 리스트 | 예약할 맛집 선택 |
| 중앙 - 달력 | 예약 가능한 날짜 표시 및 선택 |
| 우측 - 예약 정보 | 선택한 날짜·시간·인원 실시간 반영 |
| 하단 - 버튼 | 예약 시간 / 인원 선택 → 우측 예약 정보 갱신 |

## 3. 예약 처리 흐름

### 1) 예약 등록

```
날짜 선택 → 시간 버튼 클릭 → 인원 버튼 클릭
        │
        │ 예약 정보 우측 패널 실시간 갱신 (Ajax)
        ▼
예약 확정 요청 → DB 저장 → 마이페이지에서 확인
```

### 2) 마이페이지 예약 확인

- 예약 완료 후 마이페이지에서 예약 목록 조회
- 맛집명 / 예약 날짜·시간 / 인원 정보가 DB에서 조회되어 출력
- 예약 취소 / 수정 기능 연계 가능

### 3) 예약 가능 날짜 처리

- 달력에서 이미 마감된 날짜는 선택 불가 처리 (disabled 또는 스타일 구분)
- 선택 가능한 날짜만 클릭 이벤트 활성화

## 4. Ajax 비동기 처리

예약 시스템에서 Ajax를 사용하는 이유는 **버튼 클릭마다 화면 전체를 새로고침하지 않고 예약 정보 영역만 갱신**하기 위해서다.

```javascript
// 예약 시간 버튼 클릭 시 예약 정보 갱신
axios.post('/reserve/select', { time: selectedTime, date: selectedDate })
    .then(response => {
        // 우측 예약 정보 영역만 업데이트
        this.reserveInfo = response.data;
    });
```

**Controller 처리 방식**

| return 방식 | 동작 | 예약 시스템에서의 사용 |
|------------|------|-------------------|
| `return "경로"` | 화면 전환 (forward) | 예약 완료 후 마이페이지 이동 |
| `return "redirect:/..."` | 화면 전환 (redirect) | INSERT/DELETE 후 페이지 이동 |
| `void` + `@ResponseBody` | 데이터만 반환 (Ajax) | 시간·인원 선택 시 예약 정보 갱신 |

> 예약 정보 갱신처럼 화면 전환 없이 데이터만 주고받는 경우 `@RestController` + Ajax 조합을 사용한다.

## 5. 예약 데이터 설계 포인트

예약 기능 구현 시 DB 테이블과 데이터 흐름에서 고려해야 할 핵심 사항

### 1) 예약 테이블 주요 컬럼

| 컬럼 | 설명 |
|------|------|
| `reserve_no` | 예약 고유 번호 (PK) |
| `food_no` | 예약한 맛집 번호 (FK) |
| `user_id` | 예약자 ID (FK) |
| `reserve_date` | 예약 날짜 |
| `reserve_time` | 예약 시간 |
| `people_count` | 예약 인원 |
| `status` | 예약 상태 (대기 / 확정 / 취소) |

### 2) 중복 예약 방지

- 같은 날짜·시간에 이미 예약이 존재하면 해당 슬롯을 비활성화
- DB 조회로 예약 가능 여부를 확인 후 버튼 상태를 결정

### 3) 로그인 연동

- 예약은 로그인한 사용자만 가능 → `HttpSession` 또는 `Principal`로 사용자 정보 확인
- 비로그인 상태에서 예약 시도 시 로그인 페이지로 이동

### 배운 점
- 예약처럼 사용자 입력이 많은 화면은 매번 페이지를 새로고침하지 않고 Ajax로 필요한 영역만 갱신하는 것이 UX 측면에서 훨씬 자연스럽다는 것을 경험함
- 화면 전환이 필요한 경우(예약 완료 후 마이페이지 이동)와 데이터만 갱신하는 경우(시간·인원 선택)를 구분해 `@Controller` / `@RestController`를 적절히 나눠 사용하는 것이 중요함을 이해함
- 예약 시스템에서 중복 예약 방지와 로그인 여부 확인이 핵심 설계 포인트임을 이해함
