## 1. WebSocket 개요

기존 HTTP는 클라이언트가 요청해야만 서버가 응답하는 **단방향 통신** 구조다.  
WebSocket은 한 번 연결되면 서버와 클라이언트가 **양방향으로 실시간 통신**이 가능한 프로토콜로, 실시간 채팅·알림·주가 등에 사용된다.

| 구분 | HTTP | WebSocket |
|------|------|-----------|
| 통신 방향 | 단방향 (요청 → 응답) | 양방향 (실시간) |
| 연결 유지 | 요청마다 연결·해제 | 연결 유지 |
| 프로토콜 | `http://` | `ws://` |
| 주요 용도 | 일반 웹 요청 | 채팅, 알림, 실시간 데이터 |

## 2. 전체 동작 흐름

```
브라우저 접속 (ws://.../chat)
        │
        ▼
@OnOpen : WebSocket 연결
        │
        ├── HttpSession에서 id, name 가져오기
        ├── 접속자 Map에 저장
        └── 전체 사용자에게 입장 메시지 전송
        │
        ▼
@OnMessage : 메시지 수신
        │
        ├── 전체 접속자 Map 반복
        │       ├── 보낸 사람 → "my: 메시지"
        │       └── 나머지   → "you: 메시지"
        │
        ▼
@OnClose : 연결 종료
        │
        ├── Map에서 해당 사용자 삭제
        └── 전체 사용자에게 퇴장 메시지 전송
```

- 접속자 관리는 `Map<String, Session>` 으로 처리 (key: 사용자 id, value: WebSocket Session)
- 전체 브로드캐스트는 Map을 순회하며 모든 Session에 메시지 전송

## 3. HttpSession 연동

WebSocket은 기본적으로 HTTP 세션에 접근할 수 없다.  
로그인 정보(id, name)를 WebSocket 안에서 사용하려면 별도 연동 설정이 필요하다.

**연동 순서**

```
1. 사용자 로그인
        │ id, name → HttpSession에 저장
        ▼
2. WebSocket 접속 (ws://.../chat)
        │
        ▼
3. modifyHandshake() 실행
        │ HttpSession → ServerEndpointConfig의 UserProperties에 저장
        ▼
4. @OnOpen
        │ UserProperties에서 HttpSession 꺼내기
        │ → id, name 접근 가능
        ▼
5. @OnMessage : 채팅 시작
```

- `modifyHandshake()` : WebSocket 연결 전 HTTP 핸드셰이크 시점에 실행되는 메서드
- `ServerEndpointConfig.UserProperties` : WebSocket 세션에 데이터를 임시 저장하는 Map
- 이 과정을 통해 로그인된 사용자 정보를 채팅 전반에서 활용할 수 있음

---

## 4. 핵심 어노테이션

| 어노테이션 | 실행 시점 | 역할 |
|-----------|---------|------|
| `@ServerEndpoint` | - | WebSocket 엔드포인트 URL 지정 |
| `@OnOpen` | 클라이언트 연결 시 | 접속자 등록, 입장 메시지 전송 |
| `@OnMessage` | 메시지 수신 시 | 메시지 처리 및 전체 전송 |
| `@OnClose` | 연결 종료 시 | 접속자 제거, 퇴장 메시지 전송 |
| `@OnError` | 오류 발생 시 | 예외 처리 |

- `@OnOpen` / `@OnMessage` / `@OnClose` 생명주기 흐름 학습
- `modifyHandshake()`를 통한 HttpSession ↔ WebSocket 연동 학습

### 배운 점
- HTTP는 요청이 있어야 응답하는 구조라 실시간 통신에 적합하지 않고, WebSocket은 한 번 연결 후 계속 유지되는 방식이라 채팅처럼 지속적인 데이터 교환이 필요한 곳에 적합함을 이해함
- WebSocket 자체는 HTTP 세션에 접근할 수 없어 `modifyHandshake()`로 연결 시점에 세션 정보를 가져오는 과정이 필요하다는 것을 이해함
- 접속자를 Map으로 관리하면서 메시지 전송 시 보낸 사람과 나머지를 구분해 `my` / `you`로 다르게 처리하는 구조를 이해함
